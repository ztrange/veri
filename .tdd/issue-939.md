Decisions the issue left to the plan:
- The split-off in-place half of `tests/unit/stop-requested.test.sh:96-113` is named "a malformed stop request is refused on stderr with today's message, naming the modes"; the `#683` case keeps its name and its first half until the pytest pair replaces it.
- The module reads `.tdd/stop` as bytes. The first line is the bytes before the first `\n`; a file holding no `\n` at all (a zero-byte file included) reads as the empty mode, as bash's `read … || mode=""` does; NUL bytes are dropped from the line, as bash 5's `read` drops them (observed 2026-10-07: `no\0w\n` answers `now`, exit 0).
- An unreadable `.tdd/stop` (an `OSError` opening or reading a path `is_file()` accepted) takes the refusal path with `''`, and the module prints only the refusal line — no counterpart of bash's own `Permission denied` line. The pytest case forces the error at the filesystem boundary (the open), never with permission bits (#846).
- `--clear` on a directory at `.tdd/stop` lets `unlink`'s `OSError` propagate uncaught: through the shim the interpreter prints its traceback on stderr in place of `rm`'s line and exits 1, stdout empty — the 2026-10-02 decision. No wrapper turns it into 2.
- The refusal is written through `sys.stderr.buffer` (after flushing `sys.stderr`) as the UTF-8 prefix, the raw first-line bytes and `'\n`, so non-UTF-8 bytes in are bytes out under any locale.
- Run through a symlink to the script *file*, the shim keeps `"$(dirname "$0")/veri/stop_requested.py"` unresolved, so it fails with `python3`'s own text and exit 2; no case pins it.
- The floor `tests/unit/stop-requested.test.sh` keeps after the cut: `:32-40` (exit 0), `:42-48` (exit 3), `:50-63` (exit 2), the bad-argument stderr case, the split-off malformed-text case, the symlink case and `:115-127` unmodified; `:65-77`, `:79-90` and `:92-94` are cut once pytest cases assert what they asserted.
