### A range that adds or deletes a file under `tests/` or `tests/unit/` includes `claude-md-counts.test.sh` in the affected set
- affected-suites.sh asks git for the same range twice — `git diff --name-only "$range"` at :74 and `git diff --name-only --diff-filter=AD "$range" -- "$scripts/tests"` at :93. Not applied deliberately: collapsing them means one `--name-status` pass, and its rename output (`R100<tab>old<tab>new`) is a different shape from `--name-only`'s single destination path, so the dedup would silently change which paths get placed, and no case covers a rename.
- the added-or-deleted-suite rule at affected-suites.sh:89-95 sits inline in the main flow while every other placement rule lives inside `suite_of`; it cannot move there (it is a property of the range, not of one file), but it could become a named function of its own so the rule set reads as a rule set.
