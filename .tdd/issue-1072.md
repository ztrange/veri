## Notes (decisions the issue asks the plan to state; no step pins them)

- `$BASH` under a PATH lookup is the PATH string, not a symlink-resolved path (observed 2026-10-07: `bash -c 'echo $BASH'` → `/opt/homebrew/bin/bash`, itself a symlink into the Cellar), so the module names `shutil.which("bash")`.
- BSD `sed` (this Mac) keeps a last line with no final newline without one (`printf 'a\nb' | sed 's/^/    /'` → `    a\n    b`, observed 2026-10-07); GNU `sed` does the same. The module matches.
- Run through a symlink to the script *file*, both the bash script and the shim fail; the port keeps that failure (no case pins it).
- No `python3` on PATH: the shim's `exec` fails in `sh` with 127, as every shim does — stated in the PR body, not fixed.
- Quirks that look like bugs (`08` major passing, `3` alone refusing, a non-numeric Python version passing, the venv interpreter's stdout leaking) port as is and are filed as their own issues.
- The PR body pairs each cut case with its replacement, names the case beside each Order-matters branch, names the explicit-bash invocation as the port's one contract change, and quotes make profile for tests/leaf-launchable.test.sh and tests/bash-version-guard.test.sh and the wall time of the two pytest files before and after — conductor work, not steps.
