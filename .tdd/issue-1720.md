# Plan for #1720 — PRD 011 helper: watch-runs.sh blocks until a conductor exits or a slot frees, then prints one line

- [x] `watch-runs.sh` (a `/bin/sh` shim exec'ing `python3` on a new `veri/watch_runs.py`, its usage line naming only optional options, listed in `SCRIPTS.md` as its declared caller) prints `exited <issue> <state>` and exits 0 when a conductor that was live when it started exits, `<state>` being the first word of that run's state as `status.sh` reports it (`done`, `bailed`, `stopped` or `stale`); pinned by a small case with the live-conductor listing, the run state and the wait injected in-process, no real process and no real sleep ⟦criterion 1⟧
- [ ] `watch-runs.sh --target <N>` prints `slot-free <live>/<N> next <issue>` and exits 0 when fewer than N conductors are live and `solvable-issues.sh --not-running` lists an issue, `<issue>` being the first one listed; pinned by a small case with the live-conductor listing and the solvable listing injected in-process ⟦criterion 2⟧
- [ ] `watch-runs.sh --max-wait <seconds>` prints `timeout` and exits 3 when nothing actionable happened within that wait; pinned by a small case driven by an injected clock, no real sleep ⟦criterion 3⟧
- [ ] While nothing actionable happens `watch-runs.sh` prints nothing: across several polls in which no live conductor exits and no slot frees, stdout stays empty until an actionable event or the timeout line; pinned by a small case with injected listings and clock ⟦criterion 4⟧
- [ ] A `--target` or `--max-wait` whose value is not a whole number ≥ 1 (`0`, `-1`, `abc`, empty, or missing) makes `watch-runs.sh` exit 2 with a usage line on stderr before any wait or listing is taken; pinned by a small case ⟦criterion 5⟧
