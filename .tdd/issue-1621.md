# Plan for #1621 — A criterion that reverses an existing case's expectation exhausts revise: route WRONG_TEST on a contradicted case to a red that updates it

- [ ] A new script `wrong-test-route.sh <green-report> <red-test-id>` (a ported `/bin/sh` shim over a `veri/` module, unit-tested in-process) decides the leaf that follows a green whose report carries `WRONG_TEST:`: when that line names an existing test case other than the step's own red test id, it prints `red <case>` and exits 0 (route to a red that updates that case, spending no revise attempt); when the report has no `WRONG_TEST:` line, or its line names no case or only the step's own red test, it prints `revise` and exits 3; an unreadable report or bad arguments exit 2 with nothing on stdout.
