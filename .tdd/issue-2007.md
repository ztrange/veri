# Plan for #2007 — One rule for whether a run has ended: run_end.py, used by status and stop-reason

- [x] `veri/run_end.py`'s one function `run_end(run_dir)` answers (ended, cause, standing mark): when the run's `.tdd/events.jsonl`, read through `event_log`, holds a `done`, `bail` or `stop` event with no later `resume` or `step-added`, the run has ended with cause `done`, `bailed` or `stopped` and that event as its standing mark ⟦criterion 1⟧
- [x] A run with no standing mark, no live conductor (no `.tdd/conductor.pid`, or a pid that does not answer `kill -0`) and no conductor log has ended with cause `unknown` and standing mark none, instead of raising. ⟦added⟧ ⟦criterion 1⟧ ⟂ refactor pending
- [ ] A run with no standing mark whose `.tdd/conductor.pid` pid answers `kill -0` has not ended (cause none, standing mark none) only when that pid's own command line, read through `run_end`'s one replaceable command-line function, is `run-conductor.sh` or `veri/run_conductor.py` for this run's issue number. Run-conductor for another issue number, or an unrelated process whose command line merely contains `run_conductor` or the issue's digits, leaves the run ended with cause `unknown`. ⟦added⟧ ⟦criterion 1⟧
- [ ] A run with no standing mark whose conductor pid answers `kill -0` and whose own command line is not run-conductor (the `claude` child) has not ended when its parent's command line is run-conductor (`run-conductor.sh` or `veri/run_conductor.py`) for this run's issue number. The parent pid and its command line are read through `run_end`'s replaceable function(s), and a parent that is run-conductor for another issue leaves the run ended. ⟦added⟧ ⟦criterion 1⟧
- [ ] A run with no standing mark whose conductor is alive has not ended: cause none, standing mark none; the conductor is alive only when the pid in the run's `.tdd/conductor.pid` answers `kill -0` and the command line of that process, or of its parent (the pid file holds the `claude` child that run-conductor launches), is run-conductor (`run-conductor.sh` or `veri/run_conductor.py`) for this run's issue number, the command line read through one function of `run_end` that the cases replace ⟦criterion 1⟧
- [ ] A run whose events are `bail`, then `resume`, then later `launch` events, with a live conductor, has not ended and its standing mark is none: only marks after the last `resume` count ⟦criterion 2⟧
- [ ] A run with no standing mark and no live conductor whose conductor log's latest launch (the records after its last `system`/`init` record) ends in a result record whose text names a usage limit, or whose newest leaf log reports a `rate_limit` error, has ended with cause `usage-limit`; the conductor log is the run's own `.tdd/conductor-<n>.log`, else the clone's `.tdd/conductor-<n>.log` ⟦criterion 4⟧
- [ ] A run with no standing mark and no live conductor whose conductor log's latest launch has no result record has ended with cause `killed` ⟦criterion 1⟧
- [ ] A run with no standing mark and no live conductor whose conductor log's latest launch ends in a result that is not a usage limit, or that has no conductor log at all, has ended with cause `unknown`, never running ⟦criterion 1⟧
- [ ] A conductor pid that answers `kill -0` but whose process and parent are not run-conductor for this run's issue (an unrelated process, or run-conductor for another issue) counts as not alive: the run has ended with the cause read from its conductor log ⟦criterion 3⟧
