## Decisions the issues did not settle

- **FC19 for #4033.** Sub-step 2's second block did not name `$S/branch-suite.sh`, `$S/tick-ledger.sh` or
  `$S/tick-issue-criterion.sh`; its comment pointed at the `⟦full-suite⟧` paragraph instead. That comment now names
  the three, so the guard reads the block alone. The alternative was letting the guard also read the paragraph.
- **A green wait after a flake re-run** (`.tdd/ci-flake.out` non-empty) stops either script with exit 1, so the block's
  prose writes the `ci-flake` event. The alternative was writing that event inside the script.
- **DP350** says `run-done.sh` never exits 3, rather than the issue's "call it again on exit 3": it makes no wait.
- **Settled keys:** `pr_url`, `pr_number`, `ci=green`, `no_checks=1` (pr-ready-wait); `pr_url`, `metrics=<code>` when
  the render failed, `refactor_owed_render` (pr-finish); `stop_requested`, `cleared` (run-done).
- **pr-finish reuses pr-ready-wait's helpers** (`pr_url`, `ci_wait`, `answered`, `gh_answered`, `dirty`, `stacked`)
  rather than copying them.

## Review fixes (lane 24 review, NOT OK)

1. A failed `metrics.sh` render may leave `.tdd/issue-<n>-metrics.md`, untracked or modified over an earlier commit;
   the tree check before the push now leaves out exactly that path when the render failed. Real-path process case:
   a `metrics.sh` stub that writes the file and exits 1.
2. Every git and gh call in the three modules that fails is exit 2 (no answer), never the tool's own code or 1,
   as `pr_prepare.answered` does; one parametrized case per site.
3. pr-finish stops with exit 2 when `.tdd/wait-ci.err` is absent and a `⟦full-suite⟧` line is left to tick.
4. pr-ready-wait and pr-finish refuse a stacked run (`.tdd/issue-<n>-base`) with exit 2 before any call;
   `DRAFT-PR.md` says so.
