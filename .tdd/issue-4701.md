# Plan for #4701 — A step's own refactor that rewrites a recorded pin's old text bails the run needs-user instead of re-recording the pin

- [ ] pin-recheck.sh re-records a pin whose recorded old text is in no file of the repo when its changed lines (old and new text of the same line count) occur at exactly one site of its recorded file at HEAD, its recorded command goes red with the change applied there and passes with the file restored: only that pin's record in `.tdd/issue-<n>-mutations.md` is rewritten (same mutation, new old text and context), every other record, another pin on the same file included, stays byte-for-byte unchanged, no `not checked` line is printed for it, `.tdd/pin-recheck-ok` is written and it exits 0. This step adds only that path; each refusal below arrives with its own step and case. ⟦criterion 1⟧
- [ ] pin-recheck.sh does not re-record such a pin whose recorded command stays green with the change applied at that one site: its record stays byte-for-byte unchanged, the file is byte-identical to HEAD, and it prints `not checked: <file> (old text in no file of the repo)` and exits 1. ⟦criterion 3⟧
- [ ] pin-recheck.sh does not re-record such a pin whose recorded command goes red with the change applied but also fails with the file restored: its record stays byte-for-byte unchanged, the file is byte-identical to HEAD, and it prints `not checked: <file> (old text in no file of the repo)` and exits 1. ⟦criterion 2⟧
- [ ] pin-recheck.sh does not re-record such a pin whose changed lines occur at more than one site of its recorded file at HEAD: its record stays byte-for-byte unchanged, the file is byte-identical to HEAD, and it prints `not checked: <file> (old text in no file of the repo)` and exits 1. ⟦criterion 3⟧
- [ ] pin-recheck.sh does not re-record such a pin whose changed lines occur at no site of its recorded file at HEAD: its record stays byte-for-byte unchanged and it prints `not checked: <file> (old text in no file of the repo)` and exits 1. ⟦criterion 3⟧
- [ ] pin-recheck.sh does not re-record a pin whose recorded old and new text differ in line count, even when its first old line occurs at one site of its recorded file: its record stays byte-for-byte unchanged, the file is byte-identical to HEAD, and it prints `not checked: <file> (old text in no file of the repo)` and exits 1. ⟦criterion 3⟧
- [ ] pin-recheck.sh does not re-record a pin whose recorded old and new text are identical (no changed line): its record stays byte-for-byte unchanged and it prints `not checked: <file> (old text in no file of the repo)` and exits 1. ⟦criterion 3⟧
- [ ] pin-recheck.sh still replays, and does not re-record, a pin whose old text moved whole to exactly one other file, even when its changed lines also occur at one site of its recorded file: its record stays byte-for-byte unchanged and its output and exit code are those it gives today. ⟦criterion 1⟧
