# Plan for #4701 — A step's own refactor that rewrites a recorded pin's old text bails the run needs-user instead of re-recording the pin

- [ ] pin-recheck.sh re-records a mutation pin whose recorded old text is in no file of the repo when its changed lines (the record's old and new text less the lines they share at the start and at the end) occur at exactly one site of its recorded file at HEAD and its recorded command goes red with that same change applied there: the pin's record in its `.tdd/issue-<n>-mutations.md` is rewritten against that site (same mutation, new old text and context), no `not checked` line is printed for it, and the run exits 0 with the `.tdd/pin-recheck-ok` receipt written ⟦criterion 1⟧
- [ ] pin-recheck.sh leaves the record unchanged and still prints `not checked: <file> (old text in no file of the repo)`, exit 1 and no receipt, when the pin's changed lines occur at no site or at more than one site of its recorded file at HEAD ⟦criterion 3⟧
- [ ] pin-recheck.sh leaves the record unchanged and still prints `not checked: <file> (old text in no file of the repo)`, exit 1 and no receipt, when the pin's changed lines occur at exactly one site but its recorded command stays green with the change applied there ⟦criterion 3⟧
- [ ] pin-recheck.sh rewrites a re-recorded pin's record only once its recorded command has passed with the file restored after the red mutated run: when the restored run fails, the record is left unchanged, the mutated file is byte-identical to HEAD, and the pin is printed `not checked: <file> (old text in no file of the repo)` with exit 1 ⟦criterion 2⟧
