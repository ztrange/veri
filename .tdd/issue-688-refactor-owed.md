### wait-ci.sh, for a PR GitHub reports as mergeable CONFLICTING with no check on its head, exits 2 at its first poll — without waiting out its slice or a recorded deadline — with a stderr line naming the PR and saying it conflicts with its base branch, so no workflow will start until it is rebased ⟦criterion 1⟧
- `pr_head` in `wait-ci.sh` prints Python's own spelling of `mergeable` (`True`/`False`/`None`), and the main loop matches the literal `False`. A clearer form: have the Python print a word of its own, e.g. `conflicting`, so the bash side doesn't depend on how Python spells a boolean. It isn't duplication removal, so I left it alone.
- test-only | the new case in `wait-ci.test.sh` builds the stderr diagnostic as `$(cat "$work/conflict.err")` three times; it could read it once into a variable.
