### `tests-frozen.sh rerecord-rebased <ledger> <pre-rebase-sha>` re-records an upstream-only stale case: on a branch whose ledger holds a ticked earlier step with a frozen case (recorded by `record --step`), where that case was then changed only on `origin/<default>` (the branch `refs/remotes/origin/HEAD` names) and the branch was rebased onto it, the verb rewrites that earlier step's record at the case's `HEAD` body and exits 0, and the next `check-earlier` for a later step exits 0; the module's usage line names the new verb. Pinned by one medium case (`@pytest.mark.process`, a real git repository with an `origin` remote under tmp_path) in skills/tdd/scripts/tests/py/test_tests_frozen_process.py ⟦criterion 1⟧

### `rerecord-rebased` refuses a stale case the branch itself changed since its record: when the branch edited the frozen case after the record was taken and upstream also changed it, so its body at `<pre-rebase-sha>` no longer matches the record, the verb leaves that record byte for byte unchanged and names the case on stdout as `<case> (<owning step>)`. Pinned by one medium case (`@pytest.mark.process`, a real git repository) in skills/tdd/scripts/tests/py/test_tests_frozen_process.py ⟦criterion 1⟧
- `rerecord_rebased` and `rerecord_earlier` share the same loop shape (read ledger, walk `_earlier_records`, rewrite each record file); a common walker would remove it, but it needs a new abstraction and changes the existing `rerecord_earlier`
- `rerecord_rebased` lacks the error handling that `rerecord_earlier` has, for an unreadable ledger, a failing `git show` and an unwritable record, which the exit-2 spec requires (adding it is new behaviour, not a tidy-up)
