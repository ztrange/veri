Decisions the issue left to the plan, measured on 2026-10-08 against the bash script at f9d7520f4:
- `VERI_HEARTBEAT` or `VERI_TIMEOUT` set to `08` or `1.5`: every poll round writes one arithmetic-error line on stderr and that comparison reads false, so that kill never fires and a leaf that ends on its own is reported as usual. The module writes one line per round on stderr in place of bash's (`supervise: <VAR> is not a number: '<value>'`) and never fires that kill. `010` is 8, in either variable and in the settled timeout file.
- A word (`abc`) in `VERI_HEARTBEAT`, `VERI_TIMEOUT` or `VERI_STUCK_RETRIES`: the script dies at the first comparison that reads it — exit 1, one `unbound variable` line on stderr, no status line, no exit event, no `.exit`, and the leaf left running (measured: orphaned). The module does the same: return 1 with one line `supervise: <VAR> is not a number: '<value>'`, nothing written to `.exit`, the leaf not killed. Every non-numeric word is taken as unbound; a word naming a set shell variable is not resolved.
- `VERI_STUCK_RETRIES=08`: every killed attempt's check errors and reads false, so the supervisor retries without end until an attempt is not killed, one stderr line per check; `0` and `-1` never retry; `010` retries 8 times.
- `VERI_POLL` that `sleep` refuses (`abc`): the loop polls with no pause, one stderr line per round.
- A closed stdout pipe: measured, `cat` dies quietly and the supervisor still writes `<ec>\n` to `.exit` and exits `<ec>` with nothing more on stderr. The module catches the `BrokenPipeError` writing the log, writes `.exit`, returns `<ec>`, and prints nothing more, its interpreter exit included.
- A supervisor started with SIGINT ignored (as `detach-leaf.sh` starts one): measured, sent INT it keeps running and its leaf finishes, `0` in `.exit`.
- The leaf's dispositions: measured under `detach-leaf.sh`, the leaf sees SIGINT, SIGQUIT and SIGXFSZ ignored and SIGPIPE at its default. The module hands the leaf SIGPIPE at `SIG_DFL` and SIGXFSZ at `SIG_IGN` (`restore_signals=False`), TERM/INT/HUP at `SIG_DFL` unless ignored at the supervisor's start. For `veri/parallel_conductors.py`'s `Popen` launch the leaf's SIGXFSZ is `SIG_DFL` today and becomes `SIG_IGN`: the PR body names it.
- A log that cannot be decoded at recovery: the module prints nothing in place of Python's traceback and leaves `killed-stuck`.
- Run through a symlink to the script *file*, the shim keeps `"$(dirname "$0")/veri/supervise.py"` unresolved, so it fails with `python3`'s own text and exit 2; no case pins it.
- An ignored-failure site (mkdir `.tdd`, log truncation, rc removal, pid-file or owner-file write) prints one line `supervise[<name>]: could not <action> <path>: <strerror>` on stderr and goes on.
- The function returning the model without printing is extracted from `veri/leaf_model.py`'s `main` unless #931 has landed one first, which is then imported; `veri/extract_result.py`'s existing `extract` is used for recovery.
