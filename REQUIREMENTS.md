| RD20 | Taking the new skill is an explicit act: `VERI_NEW_SKILL=1` on a resume replaces the recorded commit with the fresh tip and writes a `skill-repin` event to the run worktree's `.tdd/events.jsonl`, where `metrics.sh` reads it. (`## Launching the conductor`, paragraph 5, third bullet.) | A re-pin is chosen and recorded, never silent. |
| RD21 | A fetch of origin that fails before the snapshot is exit 2, since the tip it would pin may be stale; the one exception is `cannot lock ref`, which a parallel conductor's fetch of the same clone causes, retried up to 60 fetches in all, `VERI_FETCH_RETRY_SLEEP` seconds apart (default 1, so about a minute). (`## Launching the conductor`, paragraph 5, fourth bullet.) | A stale pin is refused, and a parallel launch's lock contention is waited out. |
| RD22 | `run-conductor.sh` starts the conductor with `TMPDIR` set to a fresh `veri-run-<n>-…` directory inside the inherited one, so whatever a project's tests leave in `os.tmpdir()` goes with it: the directory is removed when the conductor exits (any exit code) and on SIGTERM, SIGINT or SIGHUP, and its path and the launcher's pid are recorded in `.tdd/issue-<n>-tmpdir-skill-commit`. (`## Launching the conductor`, paragraph 6.) | A run's scratch never outlives it. |
| RD23 | A launcher killed outright leaves the directory, and the next `run-conductor.sh` start for any issue removes each recorded `veri-run-*` directory whose pid no longer answers `kill -0`, never a live owner's, one with no record, or one outside the inherited `TMPDIR`; an unreadable record is left alone and named on stderr. (`## Launching the conductor`, paragraph 6.) | Leftovers are swept by an observed fact, and nothing live is deleted. |
| RD24 | `VERI_MIN_FREE_GB` (default 20, a whole number >= 0, `0` disables) is the free space, in GB, that the filesystems holding the inherited `TMPDIR` and the repository must each have before launch; below it the launch is exit 2, naming the path, the free GB and the variable, and so is a value that is not a whole number >= 0. (`## Launching the conductor`, paragraph 6, last sentence.) | A run does not start on a disk that would fill mid-run. |
| RD25 | The record survives only a run that got past preflight: after the conductor exits, `run-conductor.sh` keeps `.tdd/issue-<n>-skill-commit` when `.tdd/wt/<n>` is registered as a git worktree or a local `tdd/<n>-*` branch exists (what step 1.2, the first thing after preflight, creates) and removes it otherwise, whatever the conductor's exit code; an unregistered `.tdd/wt/<n>` directory, such as the one `VERI_NEW_SKILL=1` leaves, does not count, so a launch that stopped at preflight pins nothing and the next launch takes the fresh tip. (`## Launching the conductor`, paragraph 7.) | Only a run that started work keeps its pin. |
| RD26 | When no commit can be resolved at all, the launch runs unpinned, says so on stderr, and hands the conductor `VERI_SKILL_UNPINNED=1` for the plan comment (step 2.4). (`## Launching the conductor`, paragraph 8.) | An unpinned run is visible, never silent. |
| RD27 | `## Launching the conductor` is the section right after `## Install`. (Section order.) | The operator reads how to install before how to launch. |
| RD28 | The paragraph on filing names `/vfile bug\|refactor\|feature [<one line>]` and says `/vplan` turns an idea into a PRD of small sub-PRDs. | The current line would be false once F1 lands. |

## CONTEXT.md

| ID | Requirement | Why |
|---|---|---|
| GL1 | **Ledger**: the local, committed file (one per issue) that holds the plan as a checkbox list and is the source of truth for which steps are done; it is committed atomically with each cycle's code, and the issue thread mirrors it. (`## Language`, the **Ledger** entry, first two sentences.) | One file says what is done, and the issue only mirrors it. |
| GL2 | A step's green commit ticks it and marks it `⟂ refactor pending` in the same write, and that mark comes off only when the step's verify-refactor passes, so a tick alone says green, not tidied. Resume reads the ledger for the next unchecked step. _Avoid_: TODO.md (it generalizes that), state file. (`## Language`, the **Ledger** entry, rest.) | A resumed run can tell a green step from a finished one. |
| GL3 | **Cycle**: one Red→Green→Refactor pass over a single plan step, structured as red (developer writes one failing test) → verify-red (blind) → green (developer writes minimum impl) → verify-green (blind) → green commit → refactor → verify-refactor (blind, once). _Avoid_: iteration, round. (`## Language`, the **Cycle** entry.) | The term names one fixed sequence of phases. |
| GL4 | In the **Cycle** entry the refactor is one refactor leaf for the whole step: it applies the touched files' structural candidates up to `VERI_REFACTOR_BUDGET`, suite-gated, and commits each transform itself, after which the conductor checks what it left. ADR-0017 records that shape; it supersedes ADR-0010. (`## Language`, the **Cycle** entry, the refactor parenthesis and its last sentence.) | The glossary states the current refactor shape and the record that decided it. |
| GL5 | **Solvable**: the property that makes an issue veri's to take right now: it is open, carries the opt-in label, every issue under its `## Blocked by` heading is closed, and nobody has claimed it. All four hold at once or the issue is not solvable. (`## Language`, the **Solvable** entry, first two sentences.) | The four conditions are one conjunction. |
| GL6 | In the **Solvable** entry the claim is an open pull request saying `Closes #<n>`, the one mark of a run every machine can see, since veri is developed from more than one computer and `origin` is all they share. The conductor opens that draft PR as the first act after its plan commit, so it stands for the whole run rather than for its last minutes, and a bailed run leaves it open: the issue stays claimed until a human looks, which is what a bail is for. (`## Language`, the **Solvable** entry, third to fifth sentences.) | The claim is visible to every machine for the whole run. |
| GL7 | In the **Solvable** entry the lock `.tdd/wt/<n>/.tdd/conductor.pid` is not a second claim but the worktree guard, and only on the one machine that wrote it: while the pid in there still answers `kill -0`, no second conductor there may enter that live worktree and `git reset --hard` the running leaf's uncommitted work away (#170). A pid is meaningless on any other computer, so a lock nobody answers for frees the worktree and never the issue. ADR-0024 records the division of labour and the three claims rejected for it. (`## Language`, the **Solvable** entry, the lock sentences.) | The pid lock protects a live worktree on one machine and never decides who owns the issue. |
| GL8 | In the **Solvable** entry, solvable is relative to one label: `VERI_LABEL` names it and `ready-for-agent` is only the default, so the same issue can be solvable for one loop and invisible to another. That is the intended use, one label per loop when more than one loop runs against a repository, partitioning the backlog into disjoint pools rather than having both take the lowest number off one list. (`## Language`, the **Solvable** entry, the label sentences.) | Two loops on one repository drain disjoint pools. |
| GL9 | In the **Solvable** entry the print order (`priority`, then `bug`, then the rest) runs over the set the four conditions leave and never enlarges it: a `priority` or `bug` issue that is blocked, claimed or not carrying the opt-in label is still not printed, because a band says sooner and only `VERI_LABEL` says at all. _Avoid_: eligible, ready, available, unblocked (that is only one of the four). (`## Language`, the **Solvable** entry, last sentence.) | A band reorders the solvable set and never makes an issue takeable. |
| GL10 | **Selection layer**: the part of veri that decides which issue is next, and the only part that changes per rung of the scope ladder; everything below it (conductor, leaves, supervisor, blind verification, ledger) is identical at every rung. (`## Language`, the **Selection layer** entry, first two sentences.) | Growing a rung changes selection only. |
| GL11 | In the **Selection layer** entry, at rung 2 it is `solvable-issues.sh`, which prints the solvable numbers of one scope in three bands: the issues labelled `priority` first, then the `bug`s, then the rest, each band ascending by number (exit 3 when there are none). A bug labelled `low-risk` counts as the rest, and `priority` outranks `low-risk`. `VERI_PRIORITY_LABEL` names the first band's label. _Avoid_: scheduler, picker, queue. (`## Language`, the **Selection layer** entry, rest.) | The glossary states the three-band order every other document defers to. |
| GL12 | **In flight**: a conductor one `parallel-conductors.sh` invocation launched and has not yet seen finish. The set is local to one invocation: it lives in the launcher's own memory, is subtracted from what `solvable-issues.sh` prints before each launch, and nothing outside the invocation can read it. (`## Language`, the **In flight** entry, first two sentences.) | The set is in memory, local to one invocation. |
| GL13 | In the **In flight** entry two launchers on one label still collide, each seeing only its own, which is why the answer stays one label per launcher; across machines the claim is the draft PR (ADR-0024), not this set. ADR-0025 records why it is not written anywhere. _Avoid_: running (a leaf runs too), claimed (a claim is the PR). (`## Language`, the **In flight** entry, rest.) | The in-flight set is never mistaken for a claim. |
| GL14 | **Worker**: a named, long-lived session that drains its own items of the work queue one at a time (`next`, `start`, run the conductor, then `done` or `park`) until `next` finds nothing launchable. It keeps the judgement calls (merging, reading a bail); the queue's state changes are `workqueue.sh`'s. The loop it follows is `skills/tdd/WORKER.md`. _Avoid_: thread (ok as a gloss), leaf, actor. (`## Language`, the **Worker** entry.) | The glossary defines the worker and where its loop lives. |
| GL15 | **Work queue**: the file `.tdd/workqueue` in the main working tree, written only by `workqueue.sh`, that assigns issues to workers in order and records what became of each: one line per item, `<worker>`, `<issue>`, `<state>`, `<detail>` separated by tabs, with `state` one of `queued`, `running`, `merged`, `parked`, `skipped`. (`## Language`, the **Work queue** entry, first sentence.) | The glossary defines the queue file, its writer and its line shape. |
| GL16 | In the **Work queue** entry, lines are never deleted, so it is also the record of what each worker did, and no issue is `queued` or `running` for two workers at once. It is local to one machine, like the conductor's pid lock, and does not decide what is assigned: that is the selection layer's job. _Avoid_: handoff, backlog, scope (a scope is a label's pool, not an assignment). (`## Language`, the **Work queue** entry, rest.) | The queue records assignments; selection stays elsewhere. |
| GL17 | **Contract case**: a test case that drives a script only through its command-line contract (arguments, stdin, environment, stdout, stderr, exit code, files written). It survives a port to another language unchanged, and proves the port. ADR-0027. _Avoid_: integration test (unqualified). (`## Language`, the **Contract case** entry.) | The glossary defines the case that proves a port. |
| GL18 | **Implementation case**: a bash test case, in any suite, that sources a script or a `lib/` file it uses, stubs a function inside one, or asserts on the script's source text or on which bash library it sources, so it is bound to that script's bash implementation and cannot survive its port. It is defined by what it asserts about, not by the suite it lives in. (`## Language`, the **Implementation case** entry, first two sentences.) | The glossary defines the case a port cannot keep. |
| GL19 | In the **Implementation case** entry, ADR-0027 replaces each with a pytest case asserting the same behaviour, in its own commit before the port, planned as a **replaces-case step**. _Avoid_: unit test (unqualified). (`## Language`, the **Implementation case** entry, last sentence.) | A bound case is replaced before the port, never dropped. |
| GL20 | **Replaces-case step**: a ledger step marked `⟦replaces-case⟧`, whose text names a bash suite's path and one implementation case by its exact name. It licenses deleting exactly that case, and only together with a pytest case asserting the same behaviour; its Red is that pytest case failing against the code before the change. (`## Language`, the **Replaces-case step** entry, first three sentences.) | The glossary defines the `⟦replaces-case⟧` mark and what it licenses. |
| GL21 | In the **Replaces-case step** entry the mark counts against `VERI_STEP_GROWTH` only when the step is also `⟦added⟧`. ADR-0027. _Avoid_: deletion step. (`## Language`, the **Replaces-case step** entry, rest.) | A planned replacement is not plan growth. |
| GL22 | The framework grows in three rungs, each wrapping the previous, never a rewrite; issue selection changes per rung, and everything below the selection layer stays the same. (`## Scope ladder`, opening sentence.) | Each rung adds selection only. |
| GL23 | Rung 1, **Single issue**: the human names the one issue to solve (`/tdd <number>`); XP: point it at exactly one, no automated selection yet. (`## Scope ladder`, item 1.) | The base rung has no selection. |
| GL24 | Rung 2, **Loop**: `/tdd [<scope>]` runs the single-issue conductor across the solvable issues of one scope, one after another, recomputing the solvable set after every issue rather than walking a list captured once. The first bail stops the loop unless told otherwise. It adds no failure mode of its own: every outcome is one of rung 1's. (`## Scope ladder`, item 2.) | The loop always works from the current solvable set and adds no outcome. |
| GL25 | Rung 3, **Parallel**: run several issue-conductors at once over the solvable set, respecting the dependency graph, solving issues concurrently. `parallel-conductors.sh` is its selection layer, and `/tdd <scope>` runs it when `VERI_PARALLEL` is above 1: rung 2's loop, keeping up to that many supervised print-mode conductors **in flight** and re-selecting after each one finishes. ADR-0025 records the design. (`## Scope ladder`, item 3.) | The parallel rung names its selection layer, its switch and its record. |
