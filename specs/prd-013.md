**You get:** a run that hits the growth limit is ruled on for you — steps the issue's criteria

of a bail you triage by hand. **Depends on:** 013.6, 013.9.

`--criterion <k>`; a ledger change between runs is committed as `plan: rewrite`, which

and ledger*).

### 013.12: status labels

**You get:** every state a run can be in reads off the issue's labels — `taken:<lane>` running,
`pr-ready` done, `bailed`, `parked`, and the new `stopped` — and `/vready` tells you which of them
the repository lacks. **Depends on:** nothing unbuilt.

The existing names stand (settled decision 1); merged is the issue's closed state, so it gets no
label. Facts at `96acfd2c16`: `event.py` `state_labels`, given `VERI_STATE_LABEL_ISSUE` (exported

labelling; a `stop` event exists (`run_end.py` `MARKS`) and `comment.sh <n> stopped` posts
`### ⏹️ Stopped — <mode>`, but `git grep -n '"stopped"' -- skills/tdd/scripts/veri` shows no
label write. `ready_check.py` `label_row` checks only `VERI_LABEL`. Out of scope, by this spec's
call: `unlabel-issue.sh` creating `taken:<lane>` and `release-issue.sh` ensuring the opt-in label

until a human creates each lane's label, stalls every new lane.
