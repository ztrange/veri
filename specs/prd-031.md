## The goal

veri can be pointed at code no test covers. Today a refactor run refuses it: its Cover phase
reports `COVERED: no`, the run bails `uncovered`, files a coverage issue and blocks the refactor
issue on it. That coverage issue then runs as an ordinary Red → Green → Refactor issue, whose
pin verifier rejects exactly the test the situation calls for: a black-box test around a region,
which is neither lightweight nor self-contained by design.

Feathers' order (*Working Effectively with Legacy Code*) is different work, not a variation:

1. Find a **seam**: a place where the region's behaviour can be driven and observed without
   editing the region.
2. **Surround** the region with black-box tests over inputs and outputs (characterization tests).
3. **Refactor**, with those tests as the net.
4. Write any new behaviour test-first.

This PRD gives veri steps 1 and 2 as a run kind, and joins it to what veri already has for 3 (the
refactor run kind, #499) and 4 (the ordinary loop). The loop is therefore **two issues**: a
`legacy` issue that surrounds, and the refactor issue it unblocks.

## What this PRD does not hold

- **The refactor run kind** (Cover → Transform → Verify, `REFACTOR-KIND.md`): unchanged, including
  its refusal. The refusal stops being a dead end, not a rule.
- **PRD 012's BG5 and BG6** (out-of-scope refactors under a cover leaf, the `uncovered` not-done
  row), **PRD 017's** reliance on "a refactor-kind transform may not edit a test", and **PRD 018's**
  `VERI_SKIP_VERIFY`: all hold as they are.
- **Per-language seam detection.** The step names the seam; veri does not find it by parsing.
- **Coverage measurement** (line or branch percentages). A region is surrounded when mutants die.

## Decisions

Q1–Q5 are #490's five design questions.

| ID | Decision | Why, and what was rejected | State |
|---|---|---|---|
| D1 (Q1) | A **seam** is a command or callable the test can drive from outside the region without editing the region: an entry-point CLI, an exported function, an HTTP handler. The plan step names it and the region it guards. veri detects nothing per language. | It is checkable by a verifier in any language (does the test touch only the seam?). Rejected: a per-language catalogue of seam kinds, which veri would have to maintain for every target. | Mario, 2026-11-15 |
| D2 (Q2) | **Surrounded** means: every mutant in the region's recorded mutant list goes red under the new cases, re-run by script. | The region is opaque on purpose, so the predicate is about the tests, not the code. Forced by `mutation-probe.sh`'s exit codes and the #2506 decision. Rejected: a coverage percentage, which says a line ran, not that anything checked it. | Forced |
| D3 (Q3) | The characterization tests are **permanent**: committed, in the slow tier (`process`), never deleted by the run that wrote them or by the refactor they protect. A later issue may replace one with unit tests under the ordinary loop. | A refactor-kind transform may not edit tests (`REFACTOR-KIND.md:36-38`), so scaffolding removed in the same run is impossible, and a net removed after the refactor leaves the next one uncovered again. Rejected: a `scaffolding` mark and an automatic clean-up issue. | Mario, 2026-11-15 |
| D4 (Q4) | The wrap is proved by a conductor-run **mutant table** over the region, modelled on `mutation-parity.sh`: one row per mutant, each run through `mutation-probe.sh`. The developer leaf proposes mutants; the verifier may add rows; a script runs them all. The number of mutants a region owes is its own budget, `VERI_SURROUND_MUTANTS`. | One literal replace proves one behaviour, not a region. Its own axis is forced by ADR-0020: a missing mutant is not a rejected product. | Forced; default 5, Mario, 2026-11-15 |
| D5 (Q5) | Yes: the coverage issue a refusing refactor files **is** this loop's input. `coverage_blocker` adds the `legacy` label, and its `MUTATION:` criteria seed the mutant table. A human may also file a `legacy` issue by hand, naming the region. | The refusal already produces the region, the mutations and the block. Rejected: a separate intake, which would re-derive all three. | Mario, 2026-11-15 |
| D6 | The loop is two issues: the `legacy` issue runs Seam → Surround → Verify and closes; the refactor issue it blocked becomes solvable and runs as today, its Cover now answering `COVERED: yes`. | Reuses the refactor kind, `blocked_by` and selection unchanged. Rejected: one run that surrounds and then refactors, which needs a second procedure inside the first and a ledger that changes kind midway. | Mario, 2026-11-15 |
| D7 | The `legacy` label writes a `## Legacy` section at spec capture, and the procedure loads `LEGACY.md` for it, as `refactor` loads `REFACTOR-KIND.md`. | The existing hook. | Mario, 2026-11-15 |
| D8 | A region with no seam (nothing drives it without an edit) bails `no-seam`, a process bail, with the leaf's reason. Dependency-breaking edits made before any test exists (Feathers' "sprout", "extract and override") are 031.5, not the first cut. | Editing uncovered production code with no net is the risk the whole loop exists to remove; it gets its own decision and its own verifier. | Mario, 2026-11-15 |
| D9 | A new blind verifier, `verify-surround`, judges a characterization test. It passes what verify-pin rejects (heavy, not self-contained) and rejects what verify-pin does not look for: a test that reaches inside the region, asserts on internals, or edits the region. | One verifier cannot judge both artifacts (#490). | Mario, 2026-11-15 |

**What you get:** in a foreign repo, a changed file selects that repo's own suites, so a phase
runs the tests that matter instead of none or all. Every foreign-repo run gains it, legacy or not.

**Depends on:** nothing.
