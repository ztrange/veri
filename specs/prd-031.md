# PRD 031 requirements: a legacy loop — find a seam, surround the behaviour, then refactor

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: DRAFT, written on 2026-11-15 from candidate #490 ("PRD candidate: a legacy-refactoring
loop"). The decisions marked *proposed* are the planning session's recommendations and wait for
Mario's yes. 031.1 carries rows; the rest are outlines. Nothing is filed.**

## The goal

veri can be pointed at code no test covers. Today a refactor run refuses it: its Cover phase
reports `COVERED: no`, the run bails `uncovered`, files a coverage issue and blocks the refactor
issue on it. That coverage issue then runs as an ordinary Red → Green → Refactor issue, whose
pin verifier rejects exactly the test the situation calls for: a black-box test around a region,
which is neither lightweight nor self-contained by design.

Feathers' order (*Working Effectively with Legacy Code*) is different work, not a variation:

1. Find a **seam**: a place where the region's behaviour can be driven and observed without
   editing the region.
2. **Surround** the region with black-box tests over inputs and outputs (characterization tests).
3. **Refactor**, with those tests as the net.
4. Write any new behaviour test-first.

This PRD gives veri steps 1 and 2 as a run kind, and joins it to what veri already has for 3 (the
refactor run kind, #499) and 4 (the ordinary loop). The loop is therefore **two issues**: a
`legacy` issue that surrounds, and the refactor issue it unblocks.

## What this PRD does not hold

- **The refactor run kind** (Cover → Transform → Verify, `REFACTOR-KIND.md`): unchanged, including
  its refusal. The refusal stops being a dead end, not a rule.
- **PRD 012's BG5 and BG6** (out-of-scope refactors under a cover leaf, the `uncovered` not-done
  row), **PRD 017's** reliance on "a refactor-kind transform may not edit a test", and **PRD 018's**
  `VERI_SKIP_VERIFY`: all hold as they are.
- **Per-language seam detection.** The step names the seam; veri does not find it by parsing.
- **Coverage measurement** (line or branch percentages). A region is surrounded when mutants die.

## Decisions

Q1–Q5 are #490's five design questions.

| ID | Decision | Why, and what was rejected | State |
|---|---|---|---|
| D1 (Q1) | A **seam** is a command or callable the test can drive from outside the region without editing the region: an entry-point CLI, an exported function, an HTTP handler. The plan step names it and the region it guards. veri detects nothing per language. | It is checkable by a verifier in any language (does the test touch only the seam?). Rejected: a per-language catalogue of seam kinds, which veri would have to maintain for every target. | Proposed |
| D2 (Q2) | **Surrounded** means: every mutant in the region's recorded mutant list goes red under the new cases, re-run by script. | The region is opaque on purpose, so the predicate is about the tests, not the code. Forced by `mutation-probe.sh`'s exit codes and the #2506 decision. Rejected: a coverage percentage, which says a line ran, not that anything checked it. | Forced |
| D3 (Q3) | The characterization tests are **permanent**: committed, in the slow tier (`process`), never deleted by the run that wrote them or by the refactor they protect. A later issue may replace one with unit tests under the ordinary loop. | A refactor-kind transform may not edit tests (`REFACTOR-KIND.md:36-38`), so scaffolding removed in the same run is impossible, and a net removed after the refactor leaves the next one uncovered again. Rejected: a `scaffolding` mark and an automatic clean-up issue. | Proposed |
| D4 (Q4) | The wrap is proved by a conductor-run **mutant table** over the region, modelled on `mutation-parity.sh`: one row per mutant, each run through `mutation-probe.sh`. The developer leaf proposes mutants; the verifier may add rows; a script runs them all. The number of mutants a region owes is its own budget, `VERI_SURROUND_MUTANTS`. | One literal replace proves one behaviour, not a region. Its own axis is forced by ADR-0020: a missing mutant is not a rejected product. | Forced; the default (proposed: 5) is Mario's |
| D5 (Q5) | Yes: the coverage issue a refusing refactor files **is** this loop's input. `coverage_blocker` adds the `legacy` label, and its `MUTATION:` criteria seed the mutant table. A human may also file a `legacy` issue by hand, naming the region. | The refusal already produces the region, the mutations and the block. Rejected: a separate intake, which would re-derive all three. | Proposed |
| D6 | The loop is two issues: the `legacy` issue runs Seam → Surround → Verify and closes; the refactor issue it blocked becomes solvable and runs as today, its Cover now answering `COVERED: yes`. | Reuses the refactor kind, `blocked_by` and selection unchanged. Rejected: one run that surrounds and then refactors, which needs a second procedure inside the first and a ledger that changes kind midway. | Proposed |
| D7 | The `legacy` label writes a `## Legacy` section at spec capture, and the procedure loads `LEGACY.md` for it, as `refactor` loads `REFACTOR-KIND.md`. | The existing hook. | Proposed |
| D8 | A region with no seam (nothing drives it without an edit) bails `no-seam`, a process bail, with the leaf's reason. Dependency-breaking edits made before any test exists (Feathers' "sprout", "extract and override") are 031.5, not the first cut. | Editing uncovered production code with no net is the risk the whole loop exists to remove; it gets its own decision and its own verifier. | Proposed |
| D9 | A new blind verifier, `verify-surround`, judges a characterization test. It passes what verify-pin rejects (heavy, not self-contained) and rejects what verify-pin does not look for: a test that reaches inside the region, asserts on internals, or edits the region. | One verifier cannot judge both artifacts (#490). | Proposed |

## PRD 031.1: a `legacy` issue surrounds a named region under a blind verifier

**What you get:** an issue labelled `legacy` that names a region gets black-box tests around it,
each judged by a verifier that never saw the developer's reasoning, and the run ends with those
tests committed. Worth having alone: the tests exist and are verified, even before the mutant
table (031.2) raises the bar on what "surrounded" means.

**Depends on:** nothing.

| ID | Requirement | Why |
|---|---|---|
| LG1 | For an issue carrying the `legacy` label, spec capture writes a `## Legacy` section, as it writes `## Refactor` for `refactor`. An issue carrying both `legacy` and `refactor` is refused at capture, exit 2, naming both labels. | D7; one run, one kind. |
| LG2 | `skills/tdd/SKILL.md`, where it loads `REFACTOR-KIND.md` for a `## Refactor` spec, loads `LEGACY.md` for a `## Legacy` spec, and still passes its size test. | D7. |
| LG3 | `LEGACY.md` states the kind's phases in order, Seam → Surround → Verify, and that each plan step names one region (file and symbol or line range) and one seam (a command or callable outside the region). | D1, D6. |
| LG4 | The plan verifier rejects a legacy step that names no region, names no seam, or names a seam inside its own region. | D1: the seam is what makes the test black-box. |
| LG5 | A `develop-seam` leaf confirms the named seam drives the region without editing it, and reports `SEAM: <command or callable>` and `REACHES: yes\|no` with a proof line. `REACHES: no` bails with cause `no-seam`. It writes no test and edits no file. | D1, D8. |
| LG6 | `classify-bail.sh no-seam` prints the process-failure class, and `BAIL.md` names the cause. | A bail must have a classification. |
| LG7 | A `develop-surround` leaf writes cases that drive the region only through the seam, pass on the unmodified code, and edit no production file. Each case carries `@pytest.mark.process` or the target suite's slow-tier equivalent where it starts a process. | D3, D9. |
| LG8 | `prompts/verify-surround.md` tells the verifier to run the cases on the unmodified code and REJECT when one fails, when a case imports or calls anything inside the region other than the seam, when a case asserts on a value not observable at the seam, or when the diff changes any file outside the test files. | D9. |
| LG9 | `prompts/verify-surround.md` does not reject a case for being slow, for starting a process, or for depending on fixtures outside its own file. | D9: these are verify-pin's rejections and the artifact's nature. |
| LG10 | `build-verify-prompt.sh surround` accepts the same inputs as the `pin` phase and no other; no input can carry the developer's report. | The verifier is blind by construction. |
| LG11 | `surround` and `seam` are members of each closed phase list (`ledger.py`, `build_verify_prompt.py`, `build_develop_prompt.py`), and a legacy step's ledger line records `⟂ seam done` and `⟂ surround done` so a resumed run restarts at the phase not yet done. | Resume reads the committed ledger. |
| LG12 | A `verify-surround` REJECT spends `REVISE_BUDGET` like any other reject; a leaf that ends without a verdict spends `VERI_NO_VERDICT_RETRIES`. No new budget is introduced by 031.1. | Budgets stay on their axes. |
| LG13 | `VERI_SKIP_VERIFY` does not accept `surround`. | A legacy run with its one verifier skipped proves nothing. |
| LG14 | `verify-surround.md`, `develop-seam.md`, `develop-surround.md` and `LEGACY.md` are graded units with rows of their own. | Wording that decides verdicts is graded. |
| LG15 | CLAUDE.md's *Invariants* names the legacy kind and its verifier; CONTEXT.md defines **seam**, **region** and **characterization test**. | Docs change with the behaviour. |
