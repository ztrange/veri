# PRD 036 requirements: test runs and conductors sized to a test-worker budget T

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status (2026-11-18): revised against `af516fd713`; first written 2026-11-17 against `ad5e14de69`.
D1–D14 are Mario's answers of 2026-11-17; D15–D25 are his rulings of 2026-11-18, which overturn
D3, D4, D6, D8, D9, D10, D12 and D13 where they say so. 036.1 is built (#4310, v0.1591). Rows exist
for 036.2–036.4 (#4418, #4311, #4419); 036.5–036.10 are outlines. `make ceiling`, `test-ceiling.sh`,
`VERI_TEST_CEILING_FILE`, `~/.veri-test-ceiling`, the N value `auto`, `VERI_CONDUCTOR_TEST_WORKERS`,
`VERI_LOAD_WINDOW` and every event name below are working names.**

## The goal

One number, T, caps the test workers running on the machine at once, whoever started them. T exists
to keep wall-clock deadlines valid (per-case timeouts, a leaf's silence window and hard timeout) and
memory bounded, not to match the core count, so its default is a **measured ceiling**: the highest
worker count at which no case times out on this machine. A test run that finds too little of T free
queues. Under `/vdev`, a free N (`auto`) grows only as far as T supports; a fixed N narrows T to what
that N needs. When load timeouts still occur, veri lowers T, then N once T is at its floor, and says
so.

Target, stated in prose and forced by no criterion: on the development Mac, no test-case timeout or
killed-stuck leaf caused by load, at any N.

## What this PRD does not hold

- **Refusing an N Mario sets.** A fixed N is obeyed; veri lowers it only under D22, never raises it.
- **Spend.** No CI, runner or paid service changes. CI's Linux runner has no measured ceiling, so it
  keeps today's budget (D16's fallback).

## Rules every row below inherits

- A leg's share is what it registered under `~/.veri-pytest-legs`; an entry holds a share only while
  its pid runs under its recorded start time (unchanged).
- A wait is the #3989 kind: a marker naming the waiter's pid and start time, so a supervised leaf's
  hard timeout and silence window are frozen while it waits, and the wait counts toward no per-case
  timeout.
- `VERI_PYTEST_WORKERS=<n>` exported by the caller still overrides, used as given, never waiting and
  never registering (HW7).

## 036.2 — `make ceiling` measures the machine's test-worker ceiling (#4418)

What Mario gets: the highest worker count this machine runs veri's suite at with no case timeout,
measured instead of assumed, with the run it came from on record. Worth having alone: it says how
far today's budget (8 cores) is from what the machine holds. It costs only local machine time (one
full suite per step, a few hours on an otherwise idle machine); nothing gates on it and CI never runs
it.

Depends on: nothing.

## 036.5 — a fixed N narrows T to what it needs (outline)

Depends on 036.4. With a numeric `n=` in the role state, the effective T is max(2, min(ceiling,
N × d)), d = `VERI_CONDUCTOR_TEST_WORKERS` (default 1, D20), written where O10 settles and read by
the leg. `role-state.sh dev n <k>` prints the effective T beside N. Rows: HW21+, SC603+
(`role-state.sh`, `dispatch.sh` entries), D153+ (vdev's *The slot decision*). Open: O10, O11.

## 036.6 — `auto`: N follows what T has left (outline)

Depends on 036.5. `role-state.sh dev n auto` sets free N; at each slot decision `dispatch.sh` computes
N = floor((T − W_other) / d), floor 1, capped by the solvable queue (D20). A registry entry gains a
line telling a leaf's leg (`PYTEST_LEG_LOCK_WAIT_MARKER` set) from a non-conductor one, so W_other can
be summed. vdev's slot decision names `auto` and D14's cost.

## 036.7 — load timeouts lower T (outline)

Depends on 036.4. The reshaped half of the former 036.4. A leg records each case its per-case timeout
fails as an event; a load timeout (D21) is two or more such cases in different test files within
`VERI_LOAD_WINDOW` across the machine's legs, or a timed-out case that passes re-run alone. It lowers
the effective T (O12), never below 2, with a push naming the cases and the old and new T. One hung
case lowers nothing. Open: O12.

## 036.8 — N lowers itself when load timeouts persist with T at its floor (outline)

Depends on 036.7. The other half of the former 036.4. A load timeout while T is already 2 lowers N by
1, never below 1, written to the role state with `veri (load)` as who asked and pushed with the old
N, the new N and the cases. veri never raises it back (D22); the push says how Mario does. No live
run is stopped (P8). vdev's "Never change N on your own" gains this one exception in the same change
(D153+). Open: O13.

## 036.9 — a notice when test runs keep queueing (outline)

Depends on 036.4. When the waiting legs (their `core-wait` markers) grow across successive slot
decisions, `dispatch.sh` prints one notice naming the queue and advising a lower N; vdev sends it as a
`PushNotification` (D11). Printed again only after the queue drains. Changes nothing (D23). Needs
036.3's leak fix, or it reads cases' fake waits.

## 036.10 — a warning when test runs stretch past 2× their idle duration (outline)

Depends on 036.4. A `test-run` event (`veri/event_table.py:96`) whose seconds exceed twice its tier's
idle duration (O14) raises one warning naming the run, its tier and both durations, through the same
notice path. Changes nothing (D23). Open: O14.
