## The goal

When merges keep failing because GitHub is having an incident, the dev session finds that out from
GitHub's own status page, and is then authorized to work locally and land later. Development
carries on; once GitHub is back the outage's work lands on the protected `main` through one pull
request, and nothing is ever pushed to `main` directly.

How far "locally" reaches is set by the use case, not capped here: merges first, then live runs,
then new runs. Each is a sub-PRD worth having if the next never ships.

## What this PRD does not hold

- **A merge call that errored but landed** (the 502 on PR #3486): #4059 "PRD 020.3: a merge that
  errored is never re-merged over a landed PR".
- **Bounds on `queued-merge.sh`'s network calls**: #3984 "PRD 021.15".
- **Transient 5xx and rate limits on a single call**: already retried (`veri/github.py`
  `refusal_kind`, `wait-ci.sh`, `dispatch.sh`).
- **An outage of the model API**: P10 of `operator/PRINCIPLES.md`.
- **Red CI, a rebase conflict, a refused push, a billing block**: the status page explains none of
  them; `vmerge` handles each today.

## Cost

No paid API. The status API is free and unauthenticated: one read per unexplained `merge-failed`,
and during an outage one read per `VERI_GITHUB_STATUS_POLL` (default 300 s). No leaf, no CI job, no
added CI time beyond the script's own unit cases. 033.2's recovery PR is one `gates` run over the
whole outage's work in place of one per run.

## PRD 033.1: the dev session knows from GitHub's status page when it may work locally

**What you get:** after a merge fails for no reason `vmerge` names, the session tells you in one
line whether GitHub has had an incident on what the merge needs for 30 minutes. If so it stops
trying to merge, keeps the Done runs in order, and merges them when the incident closes.

**Depends on:** nothing. Worth having alone: today a failed merge has no route at all, and the
session cannot tell an outage from a fault of its own.

| ID | Requirement | Why |
|---|---|---|
| GS1 | `skills/tdd/scripts/github-status.sh [<component>…]` reads `<base>/api/v2/incidents/unresolved.json`, where `<base>` is `VERI_GITHUB_STATUS_URL` (default `https://www.githubstatus.com`). With no argument the components are Git Operations, Pull Requests, API Requests, Issues and Actions. | D4, C2. The base is a tunable so a case injects a feed. |
| GS2 | An incident *counts* when its `components` name one or more of the script's components and its `created_at` is `VERI_GITHUB_OUTAGE_MIN` minutes (default 30) or more before now. Its `impact` and the component's `status` are not read. | D1, D2. |
| GS3 | With one or more counting incidents the script exits 1 and prints one line per counting incident: its name, the matched components, its start in local time and its age in minutes. | A clean negative: GitHub answered, and it is down. |
| GS4 | With no counting incident the script exits 0. It prints `up`, or, for each incident that names one of the components but is younger than the threshold, one line `young <minutes> <name>`. | The session can say why local mode is not authorized yet. |
| GS5 | An incident whose `components` is empty or absent never counts. | C3. |

| GS7 | A `VERI_GITHUB_OUTAGE_MIN`, `VERI_GITHUB_STATUS_TIMEOUT` or `VERI_GITHUB_STATUS_POLL` that is not a positive integer is refused with exit 2 naming the variable, before any read. All three are in `TUNABLES`. | A bad threshold must not silently authorize. |

## PRD 033.2: Done runs merge into `local-main` during an outage and land on recovery (outline)

**What you get:** during an outage a finished run's work is merged locally, tagged, and built on
by the next run; when GitHub is back you get one PR with a green `gates` run, merged like any
other, and the tags are cut on `main` once it lands.

**Depends on:** 033.1.

Holds D6, D7, D8, D9 and C6: the local merge onto `local-main` and its gate; the record of each
run's capability for its tag; the queue of issue writes and its replay; the recovery PR and its
merge; the tags cut after it; rebasing what was cut from `local-main`; the record of skipped
suites. Replaces VO6's hold and VO7's merge-on-exit.

## PRD 033.3: a live run keeps going through an outage (outline)

**What you get:** a run that was mid-way when GitHub went down finishes its steps instead of
stopping at its next issue comment.

**Depends on:** 033.1; uses 033.2's queue of issue writes.

Holds: `comment.sh` and the issue mirror queue their write when `.tdd/github-outage` exists; the
Draft PR step's `wait-ci.sh` and readying are deferred to recovery. First to be measured: where a
mid-run outage actually stops a run (*Facts* has it read, not tested).

## PRD 033.4: new runs start during an outage (outline)

**What you get:** the queue keeps moving through a long outage: new runs start from issues read
before it began, cut from `local-main`.

**Depends on:** 033.2, 033.3.

Holds: a cached solvable list and issue bodies; a launch that skips `git fetch origin`, `gh api
user` and the claim label when the outage file exists, and claims on recovery; what happens when
another machine claimed the same issue meanwhile.
