# PRD 034 requirements: finished runs stack on one branch, and CI tests the stack's tip

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: decisions settled with Mario on 2026-11-16 in three rounds of questions. Written that day
from his ask. Nothing has landed. 034.1 and 034.2 carry rows; 034.3 to 034.6 are outlines. None is
filed. One decision (O1) is open and is needed by 034.3 only.**

## The goal

Development is decoupled from merges. A run that is finished and reviewed joins a standing *stack
branch* at once, with no CI wait and no merge call of its own, and the next run builds on it. CI
runs on the stack's tip, once per push. The stack lands on the protected default branch in
*slices*: pull requests cut at an issue's last commit, rebase-merged under the repository's rules.
Nothing is ever pushed to the default branch directly.

This is the mode one dev session worked in by hand through the GitHub incident of 2026-11-16,
kept on purpose now that GitHub is healthy. It is built for veri's own runs first; hand
development (`tddish`) follows in 034.6.

## What it saves, and what it does not

Stated so the plan is not read as more than it is.

- **Saved per issue:** one CI wait and one merge call, 3 to 5 minutes of lane time (*Facts*).
- **Not saved on the development machine for veri's runs:** a run already leaves the full suite to
  CI wherever a workflow triggers on pull requests. D4's lighter local check matters for hand
  development only.
- **Not touched by any landing scheme:** a review that comes back NOT OK (10 to 40 minutes of lane
  time a round, and CI caught none of those defects), CPU load on the development machine, and
  issues that re-sign the same graded unit, which still join one at a time (O2).

## What this PRD does not hold

- **Working through a GitHub outage**: PRD 033. An outage is this PRD's stack with its pushes
  deferred; see *Overlaps*.
- **A label or a path filter that skips `gates`**: rejected. With a stack the run count is already
  one per push, and prose is what the suite checks (264 of 531 test files name a `.md`).
- **GitHub's merge queue**: not offered to a repository owned by a user account, as read on
  2026-11-16; not confirmed from GitHub's documentation.
- **Making an issue larger to save a run**: never (P16). The landing is batched, not the work.

## PRD 034.1: a finished run joins the stack branch with no CI wait and no merge call

**What you get:** in a repository that names a stack branch, a run that is Done and reviewed is
on the stack within a rebase and a fast-tier run, and the next run starts from it. Its issue stays
claimed. A repository that names none works exactly as today.

**Depends on:** nothing. Worth having alone: slices are cut by hand today, and the join is the
step taken once per issue.

**Not split further:** naming the branch and joining it are one capability; a named branch nothing
joins gives the human nothing. Filing may still cut it into issues (KB rows, then KJ1 to KJ3, then
KJ4 to KJ11).

**Before filing:** check the first unknown under *Facts*. If GitHub does not mark a draft merged,
KJ7 is restated (the join closes the pull request with a comment naming the stack commit) and KJ9
reads that instead.

## PRD 034.3: a red stack tip stops the stack until it is green (outline)

**What you get:** a red `gates` on the tip never grows: nothing joins a red stack, the issue that
caused it is found, and its fix or its revert goes on top.

**Depends on:** 034.2. **Needs O1.**

Holds, as recommended in O1: a join is refused (exit 1) while the latest `gates` result on the
stack's tip is red; the culprit is found by running the red cases at each issue end since the last
green one; the culprit's run is resumed with a `⟦ci-repair⟧` step whose commit goes on the tip; a
run that bails instead is answered by a `git revert` of its issue's commits on the tip, with the
issue reopened to selection (KJ9's claim released). Consequence: the commits from the culprit to
its fix land in one slice, so KT5 treats a `⟦ci-repair⟧` or revert commit as naming its culprit's
issue.

## PRD 034.4: a slice of the stack lands on the default branch (outline)

**What you get:** the stack lands by a script and not by hand: a pull request up to
`stack-green.sh`'s commit, rebase-merged under the repository's rules, the issues closed, the tags
cut, and the rest of the stack carried onto the new default branch.

**Depends on:** 034.2; 034.3 for a red slice.

Holds D10 and C3: the cut (about 100 commits, or green and idle, or shorter at the agent's
judgement, always at `stack-green.sh`'s commit or an earlier tested issue end); the slice's pull
request with one `Closes #<n>` per issue; the merge through `queued-merge.sh`'s existing path;
tags by each issue's kind on the default branch's commits; then `git rebase --onto
origin/<default> <cut>` for the rest, refused unless the tree is unchanged, pushed under a pinned
lease. First to be measured: a live run's branch across that rewrite (*Facts*).

## PRD 034.5: the operator skills join and land without being told (outline)

**What you get:** `vdev` and `vcoord` route a Done run to review and then to a join, and cut a
slice when D10's condition holds, with the tracking pull request and the stack's state in the
status report.

**Depends on:** 034.1, 034.4.

Holds: `skills/vdev/SKILL.md` and `skills/vcoord/SKILL.md` routing; `status.sh` showing joined,
tested and landed counts; `vhandoff` carrying the stack's state.

## PRD 034.6: hand development joins the same stack (outline)

**What you get:** an issue developed by hand joins the stack the runs use, by the same join.

**Depends on:** 034.1.
