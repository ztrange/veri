# PRD 016 requirements: one user-level skill installs veri per project, under short names

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; **Why** is never shown to the grader; IDs are stable, and a dropped row
leaves a gap. Rows that change graded prose are applied in a ⟦skill-edit⟧ step.

**Status: draft.** No child is filed.

## The goal

Veri reaches a project through one user-level skill, `/vinstall`. It links into that project only
the skills the operator types, as ignored symlinks, and records how to run the project's tests.
Every veri skill has one short name.

## Decisions

| Decision | Choice | Rejected, and why |
|---|---|---|
| Ignore mechanism for links | `.git/info/exclude` | `.gitignore`: a tracked change for per-clone links |
| Test commands | the existing `veri: fast tests:` and `veri: all tests:` CLAUDE.md lines, committed | an ignored file: the facts are not host-specific; a new `.veri/` file: a fifth source |
| Committing those lines | `veri-install` branch and PR in the target repo, never merged by the skill | an uncommitted edit: invisible to runs |
| Linked skills | what the operator types: `vdev`, `vcoord`, `vplan`, `vgroom`, `vstatus`, `vreport`, `vfile`, `vstop` | all 13: listing cost for skills only a role uses |
| Unlinked skills | `tdd`, `vmerge`, `vbail`, `vjudge`, `vhandoff` | |
| How roles load unlinked skills | `vmerge`, `vbail`, `vjudge` through a subagent on the cheapest model that can do the job; `vhandoff` read by path, because it needs the role's state | true-subagent `vdev`/`vcoord`: they lose `AskUserQuestion` and add a parent turn each time a role stops |
| Long names | removed, with no alias | a typed alias: a second listing row per skill |
| `tdd` | keeps its name | `vtdd`: `skills/tdd/scripts/` and `.tdd/` are used throughout veri, and nobody types it once unlinked |
| `/veri-doctor` | dropped | re-running `/vinstall` answers the same question |
| Custom agent (`claude --agent`) to slim the default prompt | out of this PRD | the operator is considering it separately |

## 016.1: every skill has its short name

**You get:** `/vstatus` is the skill's only name, and so on for all 12. **Depends on:** nothing.

| ID | Requirement | Why |
|---|---|---|
| NM1 | Every `skills/veri-<name>/` is renamed to `skills/v<name>/`, and its frontmatter `name:` is `v<name>`. | One name, in the directory and the listing. |
| NM2 | `skills/tdd/` and its frontmatter name are unchanged. | See Decisions. |
| NM3 | A test fails when a tracked file outside `specs/` and `.tdd/` contains `veri-` followed by a renamed skill's name. | The removal stays complete, and a missed reference goes red instead of breaking a session. |
| NM4 | The test-only references in the 10 named test files follow the new names with their assertions unchanged. | A rename must not weaken a pin. |
| NM5 | Every renamed unit's `GRADED` line carries the new path and a signature from a fresh grade. | A carried-over signature would claim a grade the new text never had. |
| NM6 | The PR body reports the regrading's cost. | That cost is unmeasured and falls on this one change. |
| NM7 | The PR body gives the exact commands that repoint the operator's user-level links to the new directories, to run right after the merge. | The links in `~/.claude/skills` dangle the moment `main` moves. |

**Landing risk:** a live `vdev` or `vcoord` session reaches `../tdd/scripts/` through a directory the
merge removes from the main clone. 016.1 merges only with no operator session or conductor running.

## 016.2: `/vinstall` links a project

**You get:** `/vinstall` is the only veri skill at user level; any repo gets the skills you type by
running it once, and roles load the rest themselves. **Depends on:** 016.1.

| ID | Requirement | Why |
|---|---|---|
| IN1 | Every skill except `vinstall` carries an `.on-demand` marker. | `sync-config` then links only `vinstall` at user level, with no change in its repo. |
| IN2 | The README's install section gives one `ln -s` line, for `vinstall`. | The bootstrap on a machine without `sync-config`. |
| IN3 | `install-links.sh [repo-root]` creates `<main tree>/.claude/skills/<name>` for exactly `vdev`, `vcoord`, `vplan`, `vgroom`, `vstatus`, `vreport`, `vfile`, `vstop`. | The operator's list, in one place. |
| IN4 | Each link's target is under the veri main clone, never a worktree, even when the skill was loaded from one. | A worktree can vanish or change branch under the link. |
| IN5 | Run from a linked worktree, it installs into that repo's main tree. | Links in the main tree reach every worktree (see Facts). |
| IN6 | Each link's path is added to `.git/info/exclude` of the common git directory, once. | `git status` stays clean with no tracked change. |
| IN7 | A second run changes nothing and exits 0. A dangling veri link is repaired. | Re-running is the repair path. |
| IN8 | A path that exists and is not a symlink into veri is left untouched, and the script exits 2 naming it, before creating any link. | Never overwrite what veri did not create. |
| IN9 | Outside a git repository it exits 2. | Exit codes are the API. |
| IN10 | `install-links.sh` follows the port convention, with `status.sh` as the worked example. | |
| IN11 | `skills/vinstall/SKILL.md` runs the script, reports what it linked, and has a `REQUIREMENTS.md` it is graded against. | Prose is graded here. |
| LD1 | `vdev` and `vcoord` run `vmerge`, `vbail` and `vjudge` through a subagent on the cheapest model that can do the job, briefed to return at most 10 lines. | The body stays out of a long-lived context, which re-reads it from cache every turn (P6). |
| LD2 | `vdev` and `vcoord` load `vhandoff` by reading `<base dir>/../vhandoff/SKILL.md`. | It needs the role's own state. |
| LD3 | A test proves `<base dir>/../tdd/scripts/` and `<base dir>/../vmerge/SKILL.md` resolve when the base directory is a project-level symlink. | The whole loading scheme depends on it, and it is untested through such a link. |
| LD4 | `skills/vdev/SKILL.md` no longer says `vmerge` or `vbail` does not exist, and its fallback text is gone. | Stale prose sends a role down the wrong path today. |
| LD5 | The first run after this lands reports each subagent load's tokens against the skill body's size, in the PR or its issue. | The saving is an estimate and subagent start-up is unmeasured; a loss reopens this decision. |

**Migration, by the operator, once:** run `/vinstall` in veri and every repo veri runs on, then remove
the six user-level links. Typing `/tdd <n>` stops working; `/vdev` is the way in.

## 016.3 (outline): `/vinstall` records the test commands

Proposes both commands using `detect-test-command.sh`, confirms them with the operator, writes the
CLAUDE.md lines on a `veri-install` branch and opens a PR in the target repo. It never merges. Until
the PR merges, runs fall back to inference as they do today. Retiring `.veri/test-command` is
**open**: recommendation is to retire it here, since nothing but a human ever writes it.

## 016.4 (outline): `/vinstall` proves veri can run here

Moves PM1–PM9, TC1–TC7 and DR1–DR5's output line out of PRD 012. `/vinstall` ends with
`ready` or `not ready — <k> rows to fix`, and run preflight keeps its re-check. Costs per install:
about $0.004 for the Haiku probe (PRD 012's figure) and one run of each test tier.
