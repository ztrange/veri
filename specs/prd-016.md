## The goal

Veri reaches a project through one user-level skill, `/vinstall`. It links into that project only
the skills the operator types, as ignored symlinks, and records how to run the project's tests.
Every veri skill has one short name.

## 016.3: `/vinstall` records the test commands, and they are the only per-repo declaration

Split in two (P16): 016.3a gives the operator a way to record the commands; 016.3b retires the
file it replaces (Decisions, 2026-11-15). 016.3a goes first so that a repo still on
`.veri/test-command` migrates through it: until 016.3b lands, `detect-test-command.sh` still reads

### 016.3a: `/vinstall` proposes the test commands and opens a PR that records them

**You get:** a `/vinstall` in a project whose CLAUDE.md lacks a `veri: fast tests:` or
`veri: all tests:` line ends with an open PR in that project recording both lines, holding the
commands you confirmed. Until that PR merges, runs infer the commands as they do today.
**Depends on:** 016.2 (merged).

| ID | Requirement | Why |
|---|---|---|
| TL1 | `record-test-commands.sh <fast-cmd> <all-cmd> [repo-root]` (created by 016.3a; default the current repository) creates the branch `veri-install`, cut from the default branch's tip, holding one commit that changes only the root `CLAUDE.md`, creating the file when absent. | The commands are committed facts, not host-specific (Decisions: *Test commands*). |
| TL2 | On that commit, `detect-test-command.sh --tier fast` prints `<fast-cmd>` and `detect-test-command.sh --tier all` prints `<all-cmd>`, each exactly. | The written lines are the ones the detector reads; a quoting slip would record a command no run uses. |
| TL3 | An existing `veri: fast tests:` or `veri: all tests:` line is replaced where it stands, never duplicated, and every other line of `CLAUDE.md` is unchanged. | The detector takes the first match; a duplicate would leave the old command in force. |
| TL4 | It pushes `veri-install`, opens a PR from it against the default branch, prints the PR's URL on stdout, and exits 0. | The PR is how the target repo's owner accepts the change (Decisions: *Committing those lines*). |
| TL5 | It never merges: the PR it opened is still open when it exits. | Merging in the target repo is the owner's. |
| TL6 | The checkout it is run from keeps its branch, index and working tree as they were. | The operator may be mid-work in that checkout. |
| TL7 | When the default branch's tip already declares both lines with exactly these commands, it writes nothing, creates no branch or PR, and exits 3. | Nothing to do is not an error. |
| TL8 | When `origin` already has a `veri-install` branch, in this order: a PR from it in this repository (not a fork's) is open → it exits 3, naming that PR, whatever commit the branch holds; else the branch holds exactly the commit this run would push (same tree, same parent) → it opens the PR and exits 0; else it writes nothing, names that branch and what to do on stderr, and exits 2. The push that creates the branch is create-only: a branch someone else created since the check is refused, never moved. | An earlier PR may be awaiting review; overwriting it would discard it, while a branch whose PR was never opened is recovered by a re-run. |
| TL9 | A missing or empty command argument, or a `repo-root` outside a git repository, is exit 2 with nothing written. | Exit codes are the API. |
| TL10 | `record-test-commands.sh` follows the port convention (`status.sh` the worked example) and names no project fact (P12). | |
| TL11 | `skills/vinstall/SKILL.md`, in a new section `## Recording the test commands`, says: after `install-links.sh` exits 0, when the target repo's `CLAUDE.md` lacks a `veri: fast tests:` or a `veri: all tests:` line, run `detect-test-command.sh --tier fast` and `--tier all` on it and show the operator both commands, a tier that exits 3 shown as none found. | The operator confirms a proposal instead of composing one. |
| TL12 | The same section says the operator confirms or replaces each command, and `record-test-commands.sh` runs only with the two the operator confirmed; with no confirmation nothing is written. | A wrong guess committed is worse than none. |
| TL13 | The same section says that when `CLAUDE.md` already holds both lines, `/vinstall` asks nothing about test commands. | Re-running `/vinstall` is the repair path; it must not re-ask a settled question. |
| TL14 | The same section says to report the PR's URL, that runs infer the commands until that PR merges, and that `/vinstall` never merges it; on exit 2 it reports what the script printed and stops; on exit 3 it reports nothing to record. | The operator learns what is pending and whose move it is. |
| TL15 | TL11–TL14 are rows of `skills/vinstall/REQUIREMENTS.md`, and `skills/vinstall/GRADED` carries a signature from a fresh grade. | Prose is graded here. |
