# PRD 029 requirements: an older case a step supersedes is adapted, not a dead end

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: 029.1 landed on 2026-11-14 as `v0.1352` (PR #3781). Mario handed the decisions to the
planning session on 2026-11-13 ("keep going by yourself … solve the stoppers"), so D1–D7 are that
session's calls, each with the alternative it rejected. 029.2 carries rows and can be filed. 029.3
and 029.4 are outlines.**

## The goal

A run stops bailing when a step legitimately changes what an older test case pins. Today the
green leaf may not edit tests, so it reports the older case as superseded; the step has one free
reroute to act on such a report, and once that is spent every later report is answered with
`revise`, which green cannot act on. The run bails `revise-exhausted`, and a resume adds by hand
the step the run could have added itself: a test-only step, ahead of the stuck one, that adapts the
older case.

Target: no bail whose resume does nothing but add a test-only step ahead of the stuck step
(6 of the 61 bails read; see *Facts*). The acceptance criteria are the behaviours that force it.

## What this PRD does not hold

- **`⟦replaces-case⟧`**: it covers a bash case swapped for a pytest one (ADR-0027), not this.
- **The revise budget's size** (`REVISE_BUDGET`): the dead end is the route, not the count.
- **Bails that are system failures**: PRD 012 and the fixes already landed (#3746, #3696).
- **How a plan is written**: 029.4 changes what the plan verifier is shown, not the planner.

## Decisions

| ID | Decision | Why, and what was rejected |
|---|---|---|
| D1 | The fix leaves never delete, rename or merge a case, and are told that a case which now asserts the same thing as another stays. The older case is still rewritten to pin the criterion. | On the `red` and `supersede` routes the edited case is red evidence: verify-red requires it to fail on the unmodified code. Rejected: telling the leaf to change only what the criterion makes false, which the first draft of 029.1 did; a review showed such a case can pass on the unmodified code, which those routes send to verify-pin or reject. Adapting without pinning is the `supersede-diff` route's job. Also rejected: a guard script, which catches the deletion after the leaf has spent its attempt. |
| D2 | A superseded-case report made after the step's free reroute is spent becomes a test-only step inserted ahead of the current one, by the route script, as its `fixture` route already inserts one. It does not count against the free reroute. | Every resume did exactly this by hand. Rejected: a second free reroute, which keeps the dead end one report further on. |
| D3 | The inserted step is an ordinary step with its own blind verification, and counts toward `VERI_STEP_GROWTH`. | #3618 shows a reported case can be a real regression; the verifier, not the route, judges the edit. The growth budget is the existing bound on a run that keeps adding steps. |
| D4 | The exhausted leaf gets a third answer: a test-only step ahead of this one. | It is the answer the six bails needed and could not give. |
| D5 | The plan verifier is shown the test cases that touch the files a plan's steps name, and the planning rule is widened to inputs, fakes and call sequences. It comes last. | It prevents the class at the source but is the largest change and would not have caught #3758; D1 to D4 make the run recover whatever the plan missed. |
| D6 | Before the inserted step runs, the stuck step's uncommitted work (its Red case and its green implementation) is discarded, as the exhausted split already discards it, and the stuck step starts again from Red afterwards. | The inserted step's leaf commits its own diff and needs a clean tree; nothing in the procedure carries uncommitted work across another step's commit. The cost is one more red and verify-red for the stuck step. Rejected: stashing the work, which no part of the procedure does today and a resume could not find again. |
| D7 | The inserted step must leave the older cases true both before and after the stuck step's change, and edits no production code. | It is committed before the behaviour changes, so the suite must be green at its commit. All six resumes wrote exactly such an edit. Where no such edit exists the step's leaf says so through `⟦diff-checked⟧`'s own revise path, and the run bails as today. |

## 029.1 — the fix leaves delete no case

**What you get:** a `red-contradicted` or `red-supersede` leaf edits the named older cases and
removes no case, so the step's own Red case survives it.

**Depends on:** nothing.

| ID | Requirement | Why |
|---|---|---|
| OC1 | `prompts/develop-red-supersede.md`, in the paragraph after `{{CASES}}`, tells the leaf to delete, rename or merge no case, in the named files or any other, and that a case which now asserts the same thing as another, the step's own new case included, stays as it is. | D1; the deletion is what the verifier rejected, spending the step's one free reroute. |
| OC2 | `prompts/develop-red-contradicted.md` carries the same instruction for its one named case, in the paragraph after `{{CASE}}`. | The same failure (#3686, #3771). |
| OC3 | `prompts/develop-red-contradicted.md`'s numbered item tells the leaf to update the case in its suite's own style and to create no suite and no new case; it no longer says "add it" or "create one". | The item contradicted the prompt's own opening ("NO new test"). |
| OC4 | `prompts/develop-red-contradicted.md` is a graded unit with rows of its own. | Its wording caused bails and nothing graded it. |
| OC5 | Neither prompt tells the leaf which case is the step's own: the instruction is unconditional. | The rendered prompt does not name the step's Red case (`build_develop_prompt.py`), so a rule that depended on knowing it could not be followed. |

## 029.2 — a superseded-case report after the free reroute becomes a step ahead

**What you get:** a run whose step has spent its free reroute, and whose green still reports older
cases as superseded or contradicted, adds the test-only step itself and carries on, where today it
spends its revise budget and bails.

**Depends on:** nothing (029.1 has landed).

Read on 2026-11-14 with `origin/main` at `cab321aae9`: `wrong-test-route.sh` counts `reroute`
events of the step since the latest `resume` in `.tdd/events.jsonl` (`veri/wrong_test_route.py:281-287`),
and once one exists a `SUPERSEDED:` or `CONTRADICTS:` report falls through to `revise`, exit 3
(`:365-415`). Its `fixture` route already has the conductor insert a step before the current one
with `add-ledger-step.sh … before` (`SKILL.md:944`). The exhausted split discards the step's
uncommitted work with `git reset --hard HEAD` and `git clean -f -- <test-path>` (`REVISE.md:171-188`).
`pin-reject-route.sh --recheck` already inserts a `⟦diff-checked⟧ ⟦added⟧` step mid-run
(`SCRIPTS.md:105`). `SKILL.md` is 43 bytes under the size its test allows.

`prep` is the working name of the route.

| ID | Requirement | Why |
|---|---|---|
| PS1 | With a `reroute` event already recorded for the step since the latest `resume`, `wrong-test-route.sh`, given a report whose `SUPERSEDED:` or `CONTRADICTS:` lines name one or more cases it can resolve other than the step's own Red case, prints `prep <file::case> …` naming each and exits 0, where it printed `revise` and exited 3. | D2: the report that mattered came after the free reroute in all six bails. |
| PS2 | With no `reroute` event recorded for the step, every answer is what it is today. | The free reroute's routes are not what failed. |
| PS3 | With a `reroute` event recorded, a report that names no such case, or only the step's own Red case, still prints `revise` and exits 3; a name it cannot resolve to one defining file still exits 2 printing nothing. | Only a report the route can act on changes its answer. |
| PS4 | On `prep` the conductor discards the stuck step's uncommitted work the way the exhausted split does (`git reset --hard HEAD`, then `git clean -f -- <test-path>`), and inserts one step before the stuck step with `add-ledger-step.sh … before "<stuck step>"`, carrying the stuck step's `⟦criterion k⟧` and the mark `⟦diff-checked⟧`, whose text names every case `prep` printed and says they are to hold both before and after the stuck step's change with no production code edited. It commits the ledger and writes `event.sh reroute kind=prep` naming the cases. | D2, D6, D7; the insertion is the `fixture` route's, the discard the exhausted split's. |
| PS5 | The inserted step runs as any `⟦diff-checked⟧` step does, and once it is ticked the stuck step starts again from Red. | D3: the blind `diff` verifier, not the route, judges the edit, so a reported case that is a real regression is not waved through (#3618). |
| PS6 | A `prep` answer spends no `REVISE_BUDGET` attempt and writes no `revise` mark for the stuck step. | The budget is for a rejected product; this is a missing step. |
| PS7 | The inserted step carries `⟦added⟧` and counts toward `VERI_STEP_GROWTH`: `add-ledger-step.sh` exit 1 bails with cause `prep-owed`, naming the cases, and exit 2 bails `step-add-refused`. `classify-bail.sh prep-owed` prints the process-failure class, and `BAIL.md` names the cause. | D3: the growth budget is the existing bound on a run that keeps adding steps, and a bail must have a classification. |
| PS8 | The procedure for `prep` is stated where the conductor reads the other reroutes, and `SKILL.md` still passes its size test. | `SKILL.md` has no room; a route nobody is told about is not followed. |
| PS9 | `SCRIPTS.md`'s `wrong-test-route.sh` entry lists the `prep` answer, when it is given and its exit code. | The catalogue is where a conductor looks a script up. |
| PS10 | Every event and comment the `revise` path produced for a report that now answers `prep` is replaced by the `reroute`, `step-added` and step events of the inserted step; no bail event is written when the insertion succeeds. | ADR-0014: the log must tell what happened. |
