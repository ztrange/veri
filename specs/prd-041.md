# PRD 041 requirements: the dev session lives with autocompact

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status (2026-11-19): written against `main` at `fecc44801a`. D1–D5 are the owner's answers of
2026-11-19. Rows exist for 041.1 and 041.2; 041.2 depends on 041.1 only.**

## The goal

The dev session (`/vdev`) stops resetting itself. Claude Code's autocompact, set in the human's
own Claude Code configuration, keeps its context bounded, and veri has no part in that setting.
After a compaction the dev session re-invokes `/vdev`, which recovers from `.tdd/role-dev.state`
as it does today on a fresh start.

What goes: the Haiku resetter session, `role-growth.sh`, `reset-wait.sh`, the `request-reset`
verb, `VERI_RESET_GROWTH_DEV`, `VERI_RESET_ACK_TIMEOUT`, `VERI_RESET_MAX_PER_HOUR`, vdev's
*Resetting* and *Resetter* sections, and every desktop-only branch that exists because the dev
session reset itself (vhandoff's "writes nothing", vdev's "read no handoff file").

**Success measure, in prose and forced by no criterion:** the human never starts, briefs or
clears a resetter, and a dev session runs through a working day across compactions without a
handoff.

## Decisions

| ID | Decision | Answer |
|---|---|---|
| D1 | Scope | Retire everywhere: terminal and desktop app alike. |
| D2 | A veri-owned compaction threshold | None. The window is the human's Claude Code setting (`/autocompact`, `autoCompactWindow`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`); veri reads, sets and documents none of them. |
| D3 | A hook to re-trigger recovery after compaction | None. vdev's own text says to re-invoke `/vdev` after a compaction. A project or user hook would fire in every session of the repo; a skill-frontmatter hook did not fire on `/compact` in a probe (below). |
| D4 | Split | 041.1 the prose (the session stops resetting), 041.2 the deletion of what nothing then calls. |
| D5 | `reset-cost.sh` | Keeps its `conductor <n>` mode only; the `dev` mode goes. |

## 041.1 — the dev session stops resetting itself

**What the human gets:** a dev session that starts no resetter, never asks to be cleared, and
after a compaction re-invokes `/vdev` and recovers from the role state file. Depends on nothing.
Worth having alone: the scripts 041.2 deletes are then unreachable, not wrong.

| ID | Requirement | Why |
|---|---|---|
| R1 | `skills/vdev/SKILL.md` has no *Resetting* and no *Resetter* section, and no sentence naming a resetter, `role-growth.sh`, `reset-wait.sh`, `request-reset`, `VERI_RESET_GROWTH_DEV` or `VERI_RESET_ACK_TIMEOUT`. | The reset is gone; prose that names it would be followed. |
| R2 | vdev's *Starting* starts no session at `/vdev` time (the *Resetter* paragraph is gone), and *Recovery* no longer ends by sending an `ack`. | Nothing waits for that ack. |
| R3 | vdev's *Recovery* says: after a compaction of the dev session's own context, re-invoke `/vdev` (with the lane word when the session runs in one) before the next slot decision, which runs *Recovery* from the role state file. | The only trigger left for recovery once nothing clears the session (D3). |
| R4 | vdev names no context threshold and no autocompact setting, and says the dev session never compacts or clears itself on its own judgment. | D2: the window is the human's configuration. |
| R5 | vdev's `--resume <file>` is read in every session, the desktop app's included: the sentence restricting it to a session without `start_session`, and "read no handoff file", are gone. | D1: the desktop rule existed because the session reset itself. |
| R6 | vdev loads `vhandoff` in every session; the sentence restricting it to a session without `start_session` is gone. | Same as R5. |
| R7 | `skills/vhandoff/SKILL.md` has no branch for a session with `start_session`: `/vhandoff dev` writes the handoff in every session. Row H11 is dropped. | Same as R5. |
| R8 | vdev's *Speaking* notice list names no refused reset, no `role-growth.sh` exit 2 and no `request-reset` exit 1. | Those notices can no longer occur. |
| R9 | `operator/PRINCIPLES.md` P13 names no resetter among the sessions a message may go to, and no longer makes an exception for a recovered role's `ack` to its resetter: no message between operator sessions is answered with an `ack`. Rows P13 and P18 say the same. | The exception's only user is gone. |
| R10 | Question sessions keep using `start_session` exactly as before; no sentence about them changes. | Out of scope: they are not a reset. |
| R11 | vdev's rows D29, D52–D58, D139 and D140 are dropped, and D98 drops its reset notices; each unit whose text or rows change is regraded, and `prose-owed.sh` exits 0. | Graded prose stays signed. |

## What this PRD does not hold

- **The conductor's restart** (`restart-conductor.sh`, `VERI_RESET_GROWTH_CONDUCTOR`).
- **Any change to the human's Claude Code settings**, the `/autocompact 150000` they set on
  2026-11-19 included (D2).
- **Spend.** No CI, runner or paid service change.
