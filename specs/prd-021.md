# PRD 021 requirements: merges and stops that cannot hang, kill the wrong process or misreport

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status (2026-11-17): every sub-PRD is filed and closed: 021.1 landed as PR #3657 (tag `v0.1295`), 021.2–021.20 are #3978–#3996, and the tracker #3607 is closed. Nothing is open.**

## The goal

A stop reaches only the processes the run started. A queued merge always ends, with the merge
lock released or its holder named. A merge that landed is reported as landed. A plumbing failure
exits 2, never 1.

Target: no hand-run `merge-lock.sh release --force`, and no system bail caused by one of the
paths below. No criterion fixes a number. The criteria are the behaviours that deliver it.

## PRD 021.1: `stop-run.sh` kills only a leaf this run started

**Landed: PR #3657 (merged 2026-11-11), tag `v0.1295`.** All five rows are met. The draft's facts
were partly wrong: the pid that gets a group kill is a detached command's, written by
`detach_command.py`; a supervisor gets SIGTERM on its own pid. Both writers now record the start
time. A run on a skill snapshot older than `v0.1295` writes one-line files, so `--mode now` leaves
its supervisors running and prints one line per file; `.tdd/stop` is still written. What is left
is 021.12.

**What you get:** stopping a run cannot terminate another conductor's leaf, or any other process,
that inherited a dead leaf's pid.
**Depends on:** nothing.

## PRD 021.2: `queued-merge.sh` gives up on a head that never matches

**What you get:** a queued merge whose PR head never becomes the pushed sha ends with exit 2 and a
released merge lock, instead of holding the lock until a human intervenes.
**Depends on:** nothing.

**What the conductor does with the new exit 2 today.** The conductor calls the same
`wait-ci.sh <pr-url> 540 "" "$(git rev-parse HEAD)"` line at its `ci-timeout` sites in
`skills/tdd/DRAFT-PR.md` (*4. Draft PR*), so a head that never matches reaches it too. Before
021.2 that line exits 3 on every call and the run re-runs it without end. After 021.2 it exits 2
naming no conflict, which PRD 019.1's path handles as it handles any such exit 2: with
`VERI_ADJUDICATE_BUDGET` left (default 2 per run), an `adjudicate` leaf judges it; `retry` runs
`wait-ci.sh --fresh-window <sha>` and one more wait, which R6 makes a fresh 600 s; any other
answer, or a spent budget, writes the `ci-timeout` bail, which `classify-bail.sh ci-timeout`
labels `system`. Nothing in 021.2 changes that path.

**Depends on:** nothing.
