# PRD 021 requirements: merges and stops that cannot hang, kill the wrong process or misreport

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: DRAFT, from the 2026-11-10 code audit. 021.1–021.3 carry rows; 021.4–021.11 are
outlines. No decision has been put to Mario yet. Nothing is filed.**

## The goal

A stop reaches only the processes the run started. A queued merge always ends, with the merge
lock released or its holder named. A merge that landed is reported as landed. A plumbing failure
exits 2, never 1.

Target: no hand-run `merge-lock.sh release --force`, and no system bail caused by one of the
paths below. No criterion fixes a number. The criteria are the behaviours that deliver it.

## PRD 021.1: `stop-run.sh` kills only a leaf this run started

**What you get:** stopping a run cannot terminate another conductor's leaf, or any other process,
that inherited a dead leaf's pid.
**Depends on:** nothing.

### Requirements

| ID | Requirement | Why |
|---|---|---|
| R1 | `supervise.sh` writes a leaf's `.tdd/<name>.pid` with the pid on line 1 and the process's start time on line 2, in the form `conductor.pid` already uses. Pinned by a case. | A pid alone does not identify a process. |
| R2 | `stop-run.sh --mode now` signals a leaf's process group only when the pid file's start time equals the live process's. A pid file with no second line is never signalled, and the script prints one stderr line naming it. Pinned by a case per branch. | The file with no start time is today's file: it must stop matching. |
| R3 | A pid file whose pid is alive under a different start time is left alone, and the script's exit code is unchanged by it. Pinned by a case that fakes the process boundary. | The reuse case, stated as behaviour. |
| R4 | The guard is watched to fail: with R2's comparison removed, R3's case goes red. Recorded in the PR body. | A guard never seen red is not tested. |
| R5 | Documented through `## Requirements` rows at filing, on the `stop-run.sh` entry of `skills/tdd/SCRIPTS.md`. | Docs change with the behaviour. |

## PRD 021.2: `queued-merge.sh` gives up on a head that never matches

**What you get:** a queued merge whose PR head never becomes the pushed sha ends with exit 2 and a
released merge lock, instead of holding the lock until a human intervenes.
**Depends on:** nothing.

### Requirements

| ID | Requirement | Why |
|---|---|---|
| R1 | `wait-ci.sh`, given an expected head, records the first time it saw the PR's head differ from it, and exits 2 once that has lasted `VERI_CI_HEAD_WAIT` seconds (read as `${VERI_CI_HEAD_WAIT:-600}`), printing both shas. Pinned by a case. | The mismatched branch has no deadline today. |
| R2 | A bad `VERI_CI_HEAD_WAIT` exits 2 and names the variable. Pinned by a case. | Tunables are checked, as the others are. |
| R3 | `queued-merge.sh` releases the merge lock and exits with `wait-ci.sh`'s code when that code is neither 0 nor 3. Pinned by a case for exit 2 from R1. | The lock must not outlive the wait. |
| R4 | A head that matches again before the limit clears the record, and the wait proceeds as before. Pinned by a case. | A slow push is not a failure. |
| R5 | Documented through `## Requirements` rows at filing, on the `wait-ci.sh` and `queued-merge.sh` entries of `skills/tdd/SCRIPTS.md`. | Docs change with the behaviour. |

## PRD 021.3: a merge that landed is reported as landed

**What you get:** when the merge call succeeds and the read that confirms it fails, the tag, the
branch delete and the worktree removal still happen once the read succeeds, and a read that never
succeeds is exit 2, not "not merged".
**Depends on:** nothing.

### Requirements

| ID | Requirement | Why |
|---|---|---|
| R1 | After a merge call that exits 0, `queued-merge.sh` reads the merged state up to `VERI_MERGE_SETTLE_READS` times, `VERI_MERGE_SETTLE_SLEEP` apart: the same loop the non-zero leg uses. Pinned by a case where the first read gives no answer and the second says merged. | One failed read after a landed merge skips all cleanup today. |
| R2 | When no read gives an answer, the script releases the lock and exits 2, and its message says the merge call succeeded and its state could not be read. Pinned by a case. | "No answer" is 2. Exit 1 says the PR is not merged, which is false. |
| R3 | When a read answers "not merged" after a merge call that exited 0, the script exits 1 as today. Pinned by a case. | A real negative stays a 1. |
| R4 | Documented through `## Requirements` rows at filing, on the `queued-merge.sh` entry of `skills/tdd/SCRIPTS.md`. | Docs change with the behaviour. |

### Reported, not yet confirmed

File these only after the claim is reproduced:

- **`done_posted` under the `graphql` and `auto` drivers.** The subagent read
  `run_conductor.py:351` as calling `gh` with no arguments, so a posted `✅ Done` is missed and the
  run is marked `needs-user`. This rests on how bare `gh` exits, which nobody ran.
- **`invisible-work.sh` skips a branch by name** when any CLOSED PR once used that name
  (`invisible_work.py:123`, `:138`), so unpushed commits on a re-run branch would be hidden.
- **`workqueue.sh`'s mkdir lock** has no owner record; a kill between take and release wedges it
  until a human removes `.tdd/workqueue.lock` (`workqueue.py:57-71`). It fails loudly, in bounded
  time.
