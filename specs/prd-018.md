# PRD 018 requirements: switching blind verifiers off, phase by phase

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: 018.1 is ready to file as one issue (see its Filing section); 018.2–018.4 are outlines. Nothing is filed.**

## The goal

An operator can run veri without some of its blind verifiers. That trades checking for cost and
wall time, and each skipped verifier is a choice the operator makes visibly. Verification stays
on by default, and verify-plan cannot be skipped.

Cost target: a run with `refactor,green,red,pin,diff` skipped spends about the verifiers' share
less, 13 % at today's mix. No criterion fixes that number. The criteria are the behaviours that
deliver it.

## Decisions

Settled with Mario on 2026-11-05.

| Decision | Reason |
|---|---|
| The switch is one list, `VERI_SKIP_VERIFY=<phase>[,<phase>…]`, of `red`, `pin`, `green`, `refactor`, `diff`. Unset or empty skips nothing. | Phases differ in cost and in what they catch. A single on/off would hide which phase is being traded. |
| `plan` is refused (exit 2). | verify-plan is the cheapest verifier ($0.09 in #3052) and the only check of the plan against the issue. `criterion-finished.sh` ticks criteria from the plan's own wording. |
| A skipped phase continues as after a PASS, but is recorded as skipped: a `verify-<phase>-skipped reason=switched-off` event (the existing `nothing-landed` event, with a new reason), and `skipped` in its verdict exit file, never `0`. | Readers of verdict files (`tests_frozen.py`, the refactor-pending mark) must be able to tell "skipped" from "verified". |
| A skipped verify-green fires no `wrong-test-route.sh` route. | Those routes are verify-green REJECT outcomes, so with no verdict there is nothing to route. Accepted. |
| The list is read from the environment only, never from a label. | A label would let anyone who can label an issue switch verification off. |
| The list is pinned per run in `.tdd/issue-<n>-skip-verify` and kept across resumes. Only `VERI_NEW_SKILL=1` re-pins it. | Same rule as the skill commit: a run executes one configuration. |
| The PR body and the ✅ Done comment carry `⚠️ Unverified phases: …`, and metrics report the skipped phases. `/vmerge` is not gated. | Visible, not blocking. |
| ADR-0033 amends ADR-0003: blind verification is the default, with per-phase opt-out. It lands with this spec. | ADR-0003 states blindness as unconditional. |
| One sub-PRD per phase, refactor first. | Each phase is coupled to different machinery (P16). |

## PRD 018.1: the switch, for verify-refactor

**What you get:** a run started with `VERI_SKIP_VERIFY=refactor` finishes every step without a
verify-refactor leaf, and its PR and metrics say so. **Depends on:** nothing.

### Design calls from the site check

- **The event is the existing one, with a new reason.** It is `verify-refactor-skipped reason=switched-off`,
  not a new `verify-skipped phase=refactor`. `metrics.py:319` already counts it, and 018.2–018.4
  follow the same pattern (`verify-<phase>-skipped reason=switched-off`).
- **The verdict file says `skipped`.** The conductor writes it, and no `wait-leaf` reads it.
  `rerecord-refactored` re-records on `skipped` exactly as on `0`: the frozen record follows the
  tree. Everything else still tells `skipped` from `0`.
- **`pin-recheck.sh` still runs.** It is a mechanical check, not a verifier, and the pending-mark
  clear needs its receipt.

### Requirements

| ID | Requirement | Why |
|---|---|---|
| R1 | With `VERI_SKIP_VERIFY` naming any word other than `red`, `pin`, `green`, `refactor` or `diff` (`plan` included), the run exits 2 before its baseline, naming that word on stderr. Pinned by a case. | A typo, or `plan`, must not start a run. |
| R2 | With `VERI_SKIP_VERIFY` naming a phase that cannot be skipped yet (in 018.1, any phase but `refactor`), the run exits 2 before its baseline, naming the phase. Pinned by a case. | A phase whose machinery is not handled yet must not be skipped silently. |
| R3 | `run-conductor.sh` writes the list to `.tdd/issue-<n>-skip-verify` (empty when unset) next to the skill-commit pin. Pinned by a case. | One run, one configuration. |
| R4 | With `refactor` pinned, a step whose refactor landed launches no verify-refactor leaf. It records `verify-refactor-skipped reason=switched-off`, posts `### 🔎 verify-refactor — SKIPPED (switched off)`, and takes the PASS branch with no verdict flags. Pinned by a case. | The switch's effect for the phase. |
| R5 | That skip writes `skipped` to `.tdd/verdict-refactor.exit`. `tests-frozen.sh rerecord-refactored` re-records on `skipped` as on `0`, and still returns 3 on any other value or a missing file. | R6 | After that skip, `pin-recheck.sh` runs and `clear-refactor-pending.sh` removes the step's `⟂ refactor pending` mark, as after a PASS. A resumed run takes the step as finished. Pinned by a case. | Otherwise a resume redoes the refactor without end. |
| R7 | A run whose pinned list is not empty puts `⚠️ Unverified phases: <list>` in its PR body and its ✅ Done comment. Pinned by a case. | The trade is visible where the merge is decided. |
| R8 | `metrics.sh` prints the pinned list and the count of `reason=switched-off` skips per phase, apart from `nothing-landed` skips. Pinned by a case. | The saving can be read off the report. |

## PRD 018.2: skipping verify-green (outline)

**What you get:** `VERI_SKIP_VERIFY=green` is accepted. No verify-green leaf runs, and none of the
`wrong-test-route.sh` routes fires for the step. **Depends on:** 018.1. Open: whether the
conductor's mutation-parity check (`mutation-parity.sh`) still runs. Recommendation: yes, since
it is not a verifier leaf.

## PRD 018.3: skipping verify-red and verify-pin (outline)

**What you get:** `red` and `pin` are accepted, and a step's failing test goes to Green without
a blind check. **Depends on:** 018.1. Includes the "prediction not written" path, which today
skips both straight to revise.

## PRD 018.4: skipping verify-diff (outline)

**What you get:** `diff` is accepted, and a `⟦diff-checked⟧` step lands without a blind judge.
**Depends on:** 018.1. Open: whether `⟦skill-edit⟧` grading (`grade-prose.sh`) counts. It is a
grader, not a verifier, so the recommendation is that it stays out of the switch.
