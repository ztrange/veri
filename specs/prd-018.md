# PRD 018 requirements: switching blind verifiers off, phase by phase

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: 018.1 carries rows; 018.2–018.4 are outlines. Nothing is filed.**

## The goal

An operator can run veri without some of its blind verifiers. That trades checking for cost and
wall time, and each skipped verifier is a choice the operator makes visibly. Verification stays
on by default, and verify-plan cannot be skipped.

Cost target: a run with `refactor,green,red,pin,diff` skipped spends about the verifiers' share
less, 13 % at today's mix. No criterion fixes that number. The criteria are the behaviours that
deliver it.

## Decisions

Settled with Mario on 2026-11-05.

| Decision | Reason |
|---|---|
| The switch is one list, `VERI_SKIP_VERIFY=<phase>[,<phase>…]`, of `red`, `pin`, `green`, `refactor`, `diff`. Unset or empty skips nothing. | Phases differ in cost and in what they catch. A single on/off would hide which phase is being traded. |
| `plan` is refused (exit 2). | verify-plan is the cheapest verifier ($0.09 in #3052) and the only check of the plan against the issue. `criterion-finished.sh` ticks criteria from the plan's own wording. |
| A skipped phase continues as after a PASS, but is recorded as skipped: a `verify-skipped phase=<p>` event, and a verdict exit file whose value differs from `0`. | Readers of verdict files (`tests_frozen.py`, the refactor-pending mark) must be able to tell "skipped" from "verified". |
| A skipped verify-green fires no `wrong-test-route.sh` route. | Those routes are verify-green REJECT outcomes, so with no verdict there is nothing to route. Accepted. |
| The list is read from the environment only, never from a label. | A label would let anyone who can label an issue switch verification off. |
| The list is pinned per run in `.tdd/issue-<n>-skip-verify` and kept across resumes. Only `VERI_NEW_SKILL=1` re-pins it. | Same rule as the skill commit: a run executes one configuration. |
| The PR body and the ✅ Done comment carry `⚠️ Unverified phases: …`, and metrics report the skipped phases. `/vmerge` is not gated. | Visible, not blocking. |
| A new ADR amends ADR-0003: blind verification is the default, with per-phase opt-out. | ADR-0003 states blindness as unconditional. |
| One sub-PRD per phase, refactor first. | Each phase is coupled to different machinery (P16). |

## PRD 018.1: the switch, for verify-refactor

**What you get:** a run started with `VERI_SKIP_VERIFY=refactor` completes every step without a
verify-refactor leaf, and its PR says so. **Depends on:** nothing.

| ID | Requirement | Why |
|---|---|---|
| R1 | Preflight exits 2, before any baseline, on a `VERI_SKIP_VERIFY` naming a phase outside `red`, `pin`, `green`, `refactor`, `diff`, `plan` included, and the message names the phase. | A typo or `plan` must not start a run. |
| R2 | Preflight exits 2 on a phase this release cannot skip yet (in 018.1, any but `refactor`), naming it. | A phase whose coupled machinery is not handled must not be skipped silently. |
| R3 | At the start of the run, the conductor writes the list to `.tdd/issue-<n>-skip-verify` (empty when unset). A resume reads that file and ignores the environment, unless `VERI_NEW_SKILL=1`, which re-pins it from the environment. | One run, one configuration. |
| R4 | With `refactor` in the pinned list, the step's refactor leaf runs, but no verify-refactor leaf is launched. A `verify-skipped phase=refactor` event is written. | The switch's whole effect for the phase. |
| R5 | A skipped verify-refactor writes `.tdd/verdict-refactor.exit` with a value other than `0`, and `tests_frozen.py` treats it as "refactor done, unverified": never as a PASS, and never as a missing verdict. | `tests_frozen.py:508` must not mistake skipped for verified, or bail on it. |
| R6 | A skipped verify-refactor removes the step's `⟂ refactor pending` mark, so a resumed run takes the step as finished. | Without it, a resume would redo the refactor for ever. |
| R7 | A run with a non-empty pinned list puts `⚠️ Unverified phases: <list>` in its PR body and its ✅ Done comment. | The trade is visible where the merge is decided. |
| R8 | `metrics.sh` reports the pinned list, and the count of `verify-skipped` events per phase. | The saving and its extent can be read off the report. |
| R9 | `docs/adr/0033-*.md` records per-phase opt-out of blind verification, with verify-plan excluded, and amends ADR-0003. | ADR-0003 states blindness as unconditional. |
| R10 | `CLAUDE.md` and `SKILL.md` document `VERI_SKIP_VERIFY`, its pin and the exclusion of `plan`. | Docs change with the behaviour. |

## PRD 018.2: skipping verify-green (outline)

**What you get:** `VERI_SKIP_VERIFY=green` is accepted. No verify-green leaf runs, and none of the
`wrong-test-route.sh` routes fires for the step. **Depends on:** 018.1. Open: whether the
conductor's mutation-parity check (`mutation-parity.sh`) still runs. Recommendation: yes, since
it is not a verifier leaf.

## PRD 018.3: skipping verify-red and verify-pin (outline)

**What you get:** `red` and `pin` are accepted, and a step's failing test goes to Green without
a blind check. **Depends on:** 018.1. Includes the "prediction not written" path, which today
skips both straight to revise.

## PRD 018.4: skipping verify-diff (outline)

**What you get:** `diff` is accepted, and a `⟦diff-checked⟧` step lands without a blind judge.
**Depends on:** 018.1. Open: whether `⟦skill-edit⟧` grading (`grade-prose.sh`) counts. It is a
grader, not a verifier, so the recommendation is that it stays out of the switch.
