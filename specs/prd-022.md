# PRD 022 requirements: a run cannot be steered or damaged by text and files it does not own

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status (2026-11-17): every sub-PRD is closed: 022.1 landed as PR #3658 (tag `v0.1296`), 022.2 moved and closed as `ztrange/veri-dashboard#6`, 022.3–022.22 are #3958–#3977, and the tracker #3608 is closed. Nothing is open.**

## The goal

The repository is public. An issue body, an issue comment, a PR body and an issue title can be
written by anyone. The goal is that such text, and any file a leaf can write, cannot delete a path
outside the run, run a script in the operator's browser, stall the queue or reach the operator's
credentials.

No criterion fixes a number. The criteria are the behaviours that deliver it.

Since 2026-11-11 `ztrange/veri` has GitHub's interaction limit `collaborators_only`, so a stranger
cannot comment or open an issue there for now. The limit lasts at most six months and expires on
2027-05-11. The goal stands: veri also runs on repositories without the limit, and the limit
lapses. What changes is urgency (see 022.3).

## PRD 022.4: selection refuses an issue a stranger wrote

**You get:** an opted-in issue whose author is not `OWNER`, `MEMBER` or `COLLABORATOR` is not taken
until the operator labels it as read, and selection says why.
**Depends on:** nothing.

Site, read at `96acfd2c16`: `solvable_issues.select` lists issues through `open_listing`, whose
default route (`VERI_GH_DRIVER=rest`, `github.RestOnlyAdapter.page`) returns REST issue objects,
which carry `author_association`; the `graphql` driver's `gh issue list --json` asks for
`number,title,labels,body,state`. Today's four filters (open, opted in, unblocked, unclaimed, plus
`taken:*`, `parked` and in-flight) are the `survivors` comprehension; bands are computed for every
listed issue and only sort the survivors.

Why `MEMBER` counts here and not in 022.3: a comment 022.3 guards changes a run's state with no human
in between, so it needs write access or the operator's login; an issue is taken only after someone
with triage access applied `VERI_LABEL`, so this check is a second gate behind a human's, and an
organisation member is a known party. Both hold: they guard different readers.

|---|---|---|
| AU1 | `solvable_issues.select` keeps an issue in the solvable set only when its `author_association` is `OWNER`, `MEMBER` or `COLLABORATOR`, or it carries the label `VERI_AUTHOR_LABEL` names, in addition to today's filters. Pinned by a case per association: `OWNER`, `MEMBER`, `COLLABORATOR` printed; `CONTRIBUTOR`, `FIRST_TIME_CONTRIBUTOR`, `FIRST_TIMER`, `NONE` not. | The settled author policy (Decisions). |
