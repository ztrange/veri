# PRD 022 requirements: a run cannot be steered or damaged by text and files it does not own

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: DRAFT, from the 2026-11-10 code audit; facts re-checked 2026-11-11 against `main` at
`b7e8440a29`. Landed: 022.1 (PR #3658, tag `v0.1296`). Moved: 022.2, to be filed on
`ztrange/veri-dashboard`. Open: 022.3–022.10 (outlines; three wait on a decision). No decision has
been put to Mario yet. Nothing else is filed.**

## The goal

The repository is public. An issue body, an issue comment, a PR body and an issue title can be
written by anyone. The goal is that such text, and any file a leaf can write, cannot delete a path
outside the run, run a script in the operator's browser, stall the queue or reach the operator's
credentials.

No criterion fixes a number. The criteria are the behaviours that deliver it.

Since 2026-11-11 `ztrange/veri` has GitHub's interaction limit `collaborators_only`, so a stranger
cannot comment or open an issue there for now. The limit lasts at most six months and expires on
2027-05-11. The goal stands: veri also runs on repositories without the limit, and the limit
lapses. What changes is urgency (see 022.3).

## PRD 022.1: `issue-worktree.sh --remove` deletes only a snapshot directory veri made

**Landed: PR #3658 (merged 2026-11-11), tag `v0.1296`.** The rule differs from the draft's: the
operator's `TMPDIR` and the conductor's differ, so a parent-directory check would refuse real
snapshots. The conductor now names its snapshot `veri-snapshot-*` and writes a `.veri-snapshot`
marker holding the worktree's real path. A snapshot made before `v0.1296` has no marker, so
removing its worktree leaves it in the temp directory and says so.

**What you get:** removing a run's worktree cannot delete a path a leaf wrote into
`.snapshot-dir`.
**Depends on:** nothing.

### Requirements

| ID | Requirement | Why | State |
|---|---|---|---|
| R1 | `issue-worktree.sh --remove <n>` deletes the path in `.tdd/pinned-scripts/.snapshot-dir` only when its resolved parent is the system temp directory and its name has the prefix the conductor's snapshot directories are created with. Pinned by a case for a conforming path. | The rule `sweep_dead_runs` already applies to the same directories. | done by #3658, with another rule: prefix `veri-snapshot-`, a directory by `lstat`, and a marker naming the worktree. No temp-directory check |
| R2 | Any other content (a path elsewhere, a relative path, a symlink that resolves elsewhere, more than one line, an empty file) deletes nothing. The script prints one stderr line naming the refused path, and the worktree removal's own exit code is returned. Pinned by a case per form. | Fail closed: a deletion target read from a writable file is not trusted. | done by #3658. Two forms print nothing: an empty record, and a well-formed path to a directory already gone |
| R3 | The check and the prefix are one function shared with `run_conductor.py`'s sweep, not a second copy. Pinned by a case that the two agree on a set of paths. | Two copies of a deletion guard drift. | moot: after #3658 the two guard different directories by different rules (`veri-snapshot-` plus marker in `pinned_scripts.py:27-38`; `veri-run-` under the temp directory in `run_conductor.py:250`), so there is no second copy to share |
| R4 | The guard is watched to fail: with R1's check removed, an R2 case goes red. Recorded in the PR body. | A guard never seen red is not tested. | done by #3658 (6 cases red with `snapshot_made_for` forced true) |
| R5 | Documented through `## Requirements` rows at filing, on the `issue-worktree.sh` entry of `skills/tdd/SCRIPTS.md`. | Docs change with the behaviour. | done by #3658 |

### Low, recorded and not planned

- **`wait-ci` counts `neutral` and names no check** (`wait_ci.py:22`). The ruleset requires
  `gates` on `main`, so a PR without it cannot merge here. It matters only in a foreign
  repository with no such ruleset. Recommendation: a row under a later foreign-repo PRD.
- **Self-update is a fast-forward to `origin/HEAD`** with no signature check
  (`update_veri.py:44-58`). Whoever can push to `main` already controls the skill.
- **Step titles inside double quotes in conductor-typed commands** (`SKILL.md`; lines not
  re-read on 2026-11-11): a criterion holding `$(…)` could expand. It adds nothing over 022.5's
  exposure, since the conductor has `Bash`.
- **Placeholders are substituted in sequence** in `build_verify_prompt.py`, so a `{{FAST_CMD}}`
  string inside the issue text is expanded by a later pass. It carries no developer rationale, so
  the blind-verifier invariant holds.
