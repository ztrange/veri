# PRD 022 requirements: a run cannot be steered or damaged by text and files it does not own

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: DRAFT, from the 2026-11-10 code audit. 022.1 and 022.2 carry rows; 022.3–022.10 are
outlines, and three of them wait on a decision. No decision has been put to Mario yet. Nothing is
filed.**

## The goal

The repository is public. An issue body, an issue comment, a PR body and an issue title can be
written by anyone. The goal is that such text, and any file a leaf can write, cannot delete a path
outside the run, run a script in the operator's browser, stall the queue or reach the operator's
credentials.

No criterion fixes a number. The criteria are the behaviours that deliver it.

## PRD 022.1: `issue-worktree.sh --remove` deletes only a snapshot directory veri made

**What you get:** removing a run's worktree cannot delete a path a leaf wrote into
`.snapshot-dir`.
**Depends on:** nothing.

### Requirements

| ID | Requirement | Why |
|---|---|---|
| R1 | `issue-worktree.sh --remove <n>` deletes the path in `.tdd/pinned-scripts/.snapshot-dir` only when its resolved parent is the system temp directory and its name has the prefix the conductor's snapshot directories are created with. Pinned by a case for a conforming path. | The rule `sweep_dead_runs` already applies to the same directories. |
| R2 | Any other content (a path elsewhere, a relative path, a symlink that resolves elsewhere, more than one line, an empty file) deletes nothing. The script prints one stderr line naming the refused path, and the worktree removal's own exit code is returned. Pinned by a case per form. | Fail closed: a deletion target read from a writable file is not trusted. |
| R3 | The check and the prefix are one function shared with `run_conductor.py`'s sweep, not a second copy. Pinned by a case that the two agree on a set of paths. | Two copies of a deletion guard drift. |
| R4 | The guard is watched to fail: with R1's check removed, an R2 case goes red. Recorded in the PR body. | A guard never seen red is not tested. |
| R5 | Documented through `## Requirements` rows at filing, on the `issue-worktree.sh` entry of `skills/tdd/SCRIPTS.md`. | Docs change with the behaviour. |

## PRD 022.2: the dashboard escapes everything it did not write

**What you get:** an issue title or an event field containing HTML is shown as text on both
dashboard pages.
**Depends on:** nothing.

### Requirements

| ID | Requirement | Why |
|---|---|---|
| R1 | Every value `projects/dashboard/serve.py` interpolates into HTML that comes from an issue, a journal event or a file name passes through `html.escape`. Pinned by a case whose issue title is `<img src=x onerror=alert(1)>` and whose response holds the escaped form and not the tag. | Titles on a public repository are anyone's text. |
| R2 | The `/running` response is escaped the same way before the page assigns it to `innerHTML`. Pinned by a case with an event field holding a tag. | The second sink. |
| R3 | Each response carries a `Content-Security-Policy` header that allows no inline script. The page's script is served from its own route. Pinned by a case reading the header. | One missed escape then cannot run script. |
| R4 | The suite is `projects/dashboard`'s own (`make test TESTS="projects/dashboard/…"`). | The dashboard has its own runner. |

### Low, recorded and not planned

- **`wait-ci` counts `neutral` and names no check** (`wait_ci.py:22`). The ruleset requires
  `gates` on `main`, so a PR without it cannot merge here. It matters only in a foreign
  repository with no such ruleset. Recommendation: a row under a later foreign-repo PRD.
- **Self-update is a fast-forward to `origin/HEAD`** with no signature check
  (`update_veri.py:50-58`). Whoever can push to `main` already controls the skill.
- **Step titles inside double quotes in conductor-typed commands** (`SKILL.md:158-173`): a
  criterion holding `$(…)` could expand. It adds nothing over 022.5's exposure, since the
  conductor has `Bash`.
- **Placeholders are substituted in sequence** in `build_verify_prompt.py`, so a `{{FAST_CMD}}`
  string inside the issue text is expanded by a later pass. It carries no developer rationale, so
  the blind-verifier invariant holds.
