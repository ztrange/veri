# PRD 020 requirements: operator rules live in veri, not in one machine's memory

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: DRAFT. Mario asked on 2026-11-10 that it stay a draft. 020.0 and 020.1 carry rows;
020.2–020.6 carry each rule with its incident and site, to be cut into rows at filing. Nothing is filed.**

## The goal

A coordinator or dev session on another machine behaves like the one on the development Mac.
Today many operating rules learned from incidents live only in Claude's per-machine memory
directory (`~/.claude/projects/<veri>/memory/`). A session anywhere else never reads them and
repeats the incident. Each rule moves into the skill or principle that governs the behaviour.
When its sub-PRD merges, the memory file is deleted, so the repo is the only copy (J12).

## Sub-PRDs 020.2–020.6: the rules to port

Not yet broken into rows. Each item below carries the rule, the incident behind it and the site
it belongs at, so the sub-PRD can be filed from this file alone, on any machine. The memory files
named are on the development Mac only; each is deleted when its sub-PRD merges (Decision 2).
Paths are written generically (`<tmp>` is a scratch directory outside the session directory and
outside the worktree).

### PRD 020.2: subagent briefs that cannot damage the tree

**Site:** `skills/vdev/SKILL.md`, the review and hand-fix brief block. **Depends on:** nothing.

| Rule | Incident |
|---|---|
| Every review or hand-fix brief opens with, in bold, as its first line: **`rm` only inside the veri project directory; never outside it.** | PR #3026 (2026-11-04): two sonnet reviewers in a row ran `rm -f` on sed `.bak` files; the no-rm rule was buried mid-brief. |
| Its second line: never write `rm` in any command, not even a no-op `rm` on `/dev/null`. Mutation probes back up with `cp <file> <tmp>/<name>.orig`, mutate with a script or `perl -pi -e` (never `sed -i.<ext>`, whose backup file is left behind), and restore with `git checkout -- <file>` or `cp`. | #3561 review and #3539 merge (2026-11-10): `sed -i.mut` probes left backups the subagent could not delete, and it wrote `rm -f /dev/null` as a neutered cleanup. |
| A review's `TMPDIR` is a fresh `mktemp -d` outside the session directory; every launch puts `$VERI_VENV/bin` first on PATH. | 2026-10-10: the session-directory sandbox broke a test; #1266's preflight refused the system python 3.9. |
| A hand-run `skill-edit-step.sh` keeps issue bodies and logs outside the worktree. `skill-edit-guard.sh` refuses any untracked or modified path besides the unit, its `REQUIREMENTS.md`, `GRADED` and the ledger, and `.tdd/` is not gitignored in a fresh `.claude/worktrees/*` worktree, so a stray file discards every author attempt before grading and the step exits 1, looking like "the grader rejected every attempt". Diagnose an exit 1 by checking `.tdd/events.jsonl` for a `grading` event after each author. | #3479 (2026-11-09): three correct author attempts on `vdev/SKILL.md`, no `grading` event after them; the guard had listed sibling `issue-348x-body.md` files. |

**Memories deleted:** `review-briefs-no-rm-first`, `review-tmpdir-outside-session-dir`, `skill-edit-step-no-stray-files`.

### PRD 020.3: merges that cannot strand a PR or a lock

**Site:** `skills/vmerge/SKILL.md` (the last row: `skills/vdev/SKILL.md`, resuming a run). **Depends on:** nothing.

| Rule | Incident |
|---|---|
| After any merge error (a 502 included), poll the PR's `state` for about 2 minutes and check `git merge-base --is-ancestor <head> origin/main` before retrying. Never rebase a PR whose head, or its patch, is already on main. | PR #3486 (2026-11-09): the merge returned `502 Bad Gateway` but landed; the retry rebased onto that main and force-pushed a head equal to a main commit, so GitHub closed the PR as CLOSED, not MERGED, and #3479–#3481 never auto-closed. |
| `skills/tdd/scripts/queued-merge.sh` runs from the primary clone, never from the worktree it merges. After such a failure, confirm the lock holder's pid is dead and is yours, then run the primary clone's `merge-lock.sh release --force`. | PR #2866 (2026-11-01): run from its own worktree, cleanup removed the script's own files; it died with `FileNotFoundError` and `.tdd/merge.lock` stayed held by the dead pid while #2869's merge waited. The lock release runs after the worktree removal, from a path inside it. |
| Merge without `--admin`. A merge the ruleset refuses stops and is reported; it is never worked around. | The repository's ruleset requires a PR and allows rebase merges. |
| Every tick or fix note cites a commit's subject next to its sha, and the on-main sha is posted after the merge. | #714: a tick note pointed at a sha the rebase merge had rewritten. |
| When the issue title describes the failure, the tag message states the capability instead, proposed in the caveats message for the coordinator's ack. Example: #2204 "…words don't split…" → "Conductors and leaves run SKILL.md's bash blocks under bash, whatever the user's login shell". | Coordinator ruling 2026-10-23: a bug title as a tag reads as if the bug shipped (CLAUDE.md, *Versions are tags*). |
| One writer per worktree: before rebasing, merging or resuming in one, check nothing runs inside (`lsof +D <wt>`; `ps` for `merge-gates`, `supervise`, `claude -p`), and wait if anything does. | #159: concurrent rebases left it stale. |

**Memories deleted:** `merge-502-may-have-landed`, `queued-merge-run-from-primary`, `veri-public-main-ruleset`, `rebase-merge-rewrites-shas`, `tag-states-capability-not-bug`, `one-writer-per-worktree`.

### PRD 020.4: slots and watchers that never double-launch or go idle

**Site:** `skills/vdev/SKILL.md`, *Launching* and the bail routes. **Depends on:** nothing.

| Rule | Incident |
|---|---|
| A resume of a bailed run takes a conductor slot exactly like a new launch: count live conductors first, and while N are live, hold the resume until one exits. The ledger is fixed at once; only the launch waits. | 2026-10-29: #2591 was resumed with #2552 and #2575 live at N=2, putting 3 live; the coordinator ruled that resumes wait for a slot. |
| Before stopping or re-arming a launch watcher, run `pgrep -fl 'run_conductor.py <n>$'`. TaskStop kills only the `runwait.sh` wrapper; a detached conductor keeps running and its completion notice is lost. If it is live, do not re-arm: watch its pid (`while kill -0 <pid>; do sleep 60; done`). Compare issue numbers numerically when claiming solvable order. | 2026-10-24: #2054's watcher was stopped to reorder it behind #2259; #2054 was already live, and the re-armed watcher would have started a second conductor for it. |
| A reaped watcher is re-armed at once, without asking, and the coordinator is told: `ps -p` first, arm on the live pids, read the last comments of any that exited. | 2026-10-09: waiting for an OK left a slot empty for 45 minutes; watchers are the dev session's own plumbing. |
| Conductor scratch lives in the worktree's `.tdd/`, never a system temp directory. A leaf exit 1 with an empty report is checked against the tree and the log first. | #495: a helper in temp vanished, and the resulting exit 127 looked like progress. |

**Memories deleted:** `resume-takes-a-slot`, `check-live-before-rearming`, `rearm-reaped-watchers`, `veri-tmp-files-vanish`.

### PRD 020.5: commands that survive zsh

**Site:** `skills/vmerge/SKILL.md` (leases) and `skills/vdev/SKILL.md` *Launching*. **Depends on:** nothing.

| Rule | Incident |
|---|---|
| Brace every variable followed by a colon: `--force-with-lease=${B}:<sha>`, never `$B:<sha>` (zsh reads `:f` and the like as modifiers). On an odd push failure, rerun with `GIT_TRACE=1`. | #1592: the lease lost `:f` and git reported a fake non-fast-forward. |
| A queued launch writes each `runwait.sh` call out literally, or runs its loop under `bash -c`, or uses `${=spec}`; never `set -- $spec`, since zsh does not word-split. Check `ps -o command -p <pid>` right after launch. | 2026-10-22: `set -- $spec` launched `run_conductor.py "2183 VERI_NEW_SKILL=1 …"` as one argument; the run dropped its knobs, logged to a misnamed file, ignored SIGTERM, and needed `stop-run.sh --mode now` and a hand reset of its worktree. |

**Memories deleted:** `zsh-colon-modifier-in-lease`, `zsh-no-word-split-launch-queues`.

### PRD 020.6: one run per requirements file, and triage authority

**Site:** `skills/vdev/SKILL.md` (slot choice) and `skills/vgroom/SKILL.md` (triage). **Depends on:** nothing.

| Rule | Incident |
|---|---|
| Before arming a run, check its issue for `⟦skill-edit⟧` or `## Requirements`. Two runs that edit units of the same `REQUIREMENTS.md` file do not run at once (`SKILL.md` units count as `skills/tdd/REQUIREMENTS.md`); units of different requirements files, and code-only runs, fill any slot. A holder whose PR waits on a human decision frees the slot. Whichever PR merges second rebases onto main and reruns its regrade before merging (a `GRADED` conflict is a rebase-regrade, never a park), and reports that cost to the coordinator. | Coordinator rulings 2026-10-23 to 10-30: two concurrent regrades of one file conflict on `GRADED`; loosened step by step (Mario, 10-24: the rule was the coordinator's, so it could be loosened), since snapshot pinning leaves the same requirements file as the only collision. |
| The coordinator comments on and closes issues on its own repo without asking, with reason and evidence in the comment and one line in its report. Not other repos, not deletes, not issues a run holds, not PRs. | Triage stalled on approvals Mario always gave. |

**Memories deleted:** `skillmd-slot-one-at-a-time`, `issue-comment-close-authorized`.
