# PRD 020 requirements: operator rules live in veri, not in one machine's memory

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: DRAFT. Mario asked on 2026-11-10 that it stay a draft. 020.0 and 020.1 carry rows;
020.2–020.6 are outlines. Nothing is filed.**

## The goal

A coordinator or dev session on another machine behaves like the one on the development Mac.
Today many operating rules learned from incidents live only in Claude's per-machine memory
directory (`~/.claude/projects/<veri>/memory/`). A session anywhere else never reads them and
repeats the incident. Each rule moves into the skill or principle that governs the behaviour.
When its sub-PRD merges, the memory file is deleted, so the repo is the only copy (J12).

## Decisions

Settled with Mario on 2026-11-10.

| Decision | Reason |
|---|---|
| Each sub-PRD is a veri run, filed through `/vfile`, not a hand edit. | J5 (veri fixes veri). The rows are graded. |
| A memory file is deleted when the sub-PRD that ports it merges. | Two copies drift apart. The repo copy is the one every machine reads. |
| `vjudge` gets a requirements list first (020.0), mirroring its prose as it is. | Its rules decide what reaches the human, and nothing grades them. Later edits to it, including this PRD's, are then graded. |
| The 23 ungraded prompt files are out of scope. | They are leaf prompts, not operator rules. **Open:** a separate PRD; recommendation below. |

## PRD 020.1: every operator role, not just the coordinator, puts a decision as plain text

**What you get:** the dev session can no longer block overnight on a question tool either; a pending
decision is restated when you next write, from either role.
**Depends on:** nothing.

### Requirements

| ID | Requirement | Why |
|---|---|---|
| R1 | `operator/PRINCIPLES.md` states, as one principle: an operator role never asks the human through a question tool (`AskUserQuestion`) or a blocking end-of-turn box; a decision goes out once as plain text; only its own item waits; it is not repeated on routine turns; when the human's next message arrives, whatever it is about, the role answers it and then restates every pending decision in full. | 2026-11-10: the coordinator blocked overnight; vdev has the same exposure. |
| R2 | `operator/REQUIREMENTS.md` carries a row for that principle, and `operator/GRADED` is regraded PASS. | Graded unit. |
| R3 | vcoord's C34 sentence is reduced to a pointer to the principle, or left as is if the grader needs it. The rule is stated once. | One rule, not two restatements. |
| R4 | The memory file `coordinator-never-blocks-on-question-box.md` is deleted after merge, and its `MEMORY.md` line removed. | Decision 2. |

## Outlines

Each ports the listed memory files, then deletes them on merge.

- **020.2 — subagent briefs** (`skills/vdev/SKILL.md` brief block): review TMPDIR outside the
  session dir; "rm only inside the project dir" as the bold first line, with no `rm` even on
  `/dev/null`; probes by `cp` + `git checkout`, never `sed -i.ext`; hand-run `skill-edit-step.sh`
  bodies and logs outside the worktree. Memories: `review-tmpdir-outside-session-dir`,
  `review-briefs-no-rm-first`, `skill-edit-step-no-stray-files`.
- **020.3 — merge safety** (`skills/vmerge/SKILL.md`): after a merge error, re-read PR state about
  2 minutes later and never rebase-and-retry; run queued-merge from the primary clone, never the
  worktree it removes; merge without `--admin`, and a refused merge stops and reports; cite a
  commit's subject next to its on-main sha; reword a bug-phrased title into the capability for
  the tag; one writer per worktree (`lsof`/`ps` before resuming). Memories: `merge-502-may-have-landed`,
  `queued-merge-run-from-primary`, `veri-public-main-ruleset`, `rebase-merge-rewrites-shas`,
  `tag-states-capability-not-bug`, `one-writer-per-worktree`.
- **020.4 — slots and watchers** (`skills/vdev/SKILL.md`): a bailed run's resume counts against N;
  check the conductor is alive (`pgrep`) before stopping or re-arming a watcher, since TaskStop
  leaves the conductor running; re-arm a reaped watcher at once and tell the coordinator; keep
  conductor scratch in the worktree's `.tdd/`. Memories: `resume-takes-a-slot`,
  `check-live-before-rearming`, `rearm-reaped-watchers`, `veri-tmp-files-vanish`.
- **020.5 — zsh** (vmerge, vdev *Launching*): write `${B}:<sha>` in leases; never `set -- $spec` for
  a conductor's arguments. Memories: `zsh-colon-modifier-in-lease`, `zsh-no-word-split-launch-queues`.
- **020.6 — one session per graded directory** (vdev or vcoord): one holder edits a `GRADED`
  directory at a time; a holder waiting on a human decision frees it; the second to merge rebases
  and regrades. Memory: `skillmd-slot-one-at-a-time`.
- Triage authority (`issue-comment-close-authorized`) goes into `vgroom` with 020.6 or on its own;
  it is too small to be its own capability.
