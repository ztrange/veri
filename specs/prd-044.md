# PRD 044 requirements: a pin step writes no test

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap. A row whose ID is an existing
one (`CY123`) rewords that row in place; a new row takes its prefix's next free number.

**Status (2026-11-24): written against `main` at `876b43e148`. D1–D6 are the owner's answers of
2026-11-24. Rows exist for 044.1 only; 044.2 is an outline.**

## The goal

A step whose criterion already holds at the branch base is a **pin** (CONTEXT.md): today its
developer writes a test, and verify-pin demands that the test fail at the base under a hand
mutation, which the probe records in `.tdd/issue-<n>-mutations.md`. `pin-recheck.sh` replays every
recorded mutation over each later refactor, and a finding becomes a re-pin step or a bail.

In Beck's TDD a test is added while developing, or as a bug's repro. A test that passes from the
start drove nothing. The recorded mutations bind to literal source text, so a later refactor that
rewrites those lines owes a re-pin or bails, and no recorded catch of a real regression was found
(*Facts*). This PRD first removes the recording and the recheck (044.1), then stops a pin step from
writing a test where an existing one already covers its criterion (044.2).

**Target, in prose and forced by no criterion:** fewer re-pin steps and pin-recheck plumbing issues,
and no refactor step bailed over a recorded mutation.

The spec also makes these calls, unasked:

- **A `⟦go-red⟧` step ticks on a run-state receipt, not on the record.** `tick-ledger.sh` refuses a
  `⟦go-red⟧` tick today unless the mutation record holds the step's probe (GRD3). 044.1 keeps that
  guard by moving it: `go-red-step.sh` writes the untracked `.tdd/go-red-probed` (the probe line and
  `HEAD`'s sha) after `mutation-probe.sh` exits 0, and the tick requires it. The alternative, dropping
  the guard because `go-red-step.sh` ticks only after exit 0, leaves a hand tick unchecked.
- **A go-red control loses its record check.** `tick-ledger.sh`'s exit 2 when the record holds no
  line for a named control (PN26) goes; the control still forces a verify-pin run, which is the
  evidence. The alternative, keeping a record for controls only, keeps the file this PRD deletes.
- **The merge-time stale-record checks go with the records**: `queued-merge.sh`'s and
  `run-finished.sh`'s refusal of a stale mutation-record pin (`mutation_record.stale_pins`).
- **Everything that only served the records goes**: supervise's record restore and its
  `mutation-record-restored` event, the plan's `mutation-record:` directive, `VERI_MUTATION_RECORD`,
  the `.gitignore` and `ensure-run-state-ignored.sh` admissions, and the `pin-retired` event.
- **The verify-pin prompt is unchanged in 044.1.** `prompts/verify-pin.md` never mentions recording;
  recording stops where `veri/verify.py` sets `VERI_MUTATION_RECORD` for the pin phase.
- **No `CLAUDE.md` row.** `grep -n -i 'pin-recheck\|mutations\.md' CLAUDE.md` finds nothing at
  `876b43e148`; its one `repin` hit is the `skill-repin` snapshot event, unrelated.
- **PRD 043 is not edited here.** Its D5 lists pin-recheck as waivable and its 043.4 outline is
  pin-recheck; 044.1 makes both moot, and 044.2 makes moot the verify-pin fail-at-base waiver 043
  already dropped (`3b33e78b00` "docs: PRD 043 drops 043.3, the verify-pin fail-at-base waiver",
  on branch `docs/prd043-drop-3`). Striking them is PRD 043's own change.

## 044.1: no recorded mutation, no pin-recheck

**What the human gets:** a refactor that rewrites a pinned line no longer owes a re-pin step or bails
`repin-failed`/`not-checked`, and a run carries no mutation records to keep fresh. Pins are still
written and verified as today. Depends on nothing; worth having if 044.2 never ships.

## 044.2 (outline): an already-holding step writes no test

**What the human gets:** a step whose criterion already holds costs a verifier's read of named tests
instead of a new test, a mutation and a possible `unpinnable` retire. Depends on 044.1, which removed
what a pin without a mutation would otherwise break. Worth having alone: it ends tests that drove
nothing.

- D1: the developer names existing tests; a new blind verify phase (inputs: the criterion and the
  named test files only, held to `build-verify-prompt.sh`'s blindness check) judges coverage; PASS
  ticks the step `⟂ already holds`.
- D2: a bug criterion already fixed takes D1, then D3.
- D3: no covering test → one written, judged only for covering the criterion.
- verify-pin's fail-at-base and hand-mutation demands go, with the `unpinnable` retire and
  `pin-reject-route.sh`'s unpinnable route.
- A new ADR (0039 if none lands first) supersedes ADR-0012's pin-test part; CONTEXT.md's **Pin**
  is reworded.
- #4739 is closed as moot when this lands.

## What this PRD does not hold

- **`mutation-parity.sh`** (ADR-0030). It checks a mutation tool's parity, not a pin's record, and
  stays.
- **The `legacy` kind's surround mutants** (`VERI_SURROUND_MUTANTS`). They are not pin records.
- **Rewriting existing pin tests.** Tests already on `main` stay.
- **Spend.** No CI, runner or paid-service change. 044.1 removes leaf launches (re-pin steps); 044.2
  swaps a developer-plus-verifier pin for a verifier read where tests exist.
