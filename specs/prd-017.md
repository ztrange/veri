# PRD 017 requirements: three deep modules under the hot spots

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status (2026-11-17): every sub-PRD is filed and closed: 017.1 (#2892–#2897, #2931, #2970), 017.2 (#3939–#3944), 017.3 (#3049–#3053, #3077), 017.4–017.14 (#3945–#3957). Open: the tracker #2891 and three cases folded in from later work, #4294 (case_reader cuts a JS regex literal), #4295 (check-earlier accepts a file that is not the run's ledger) and #4296 (rerecord-refactored writes a pass marker nothing reads).**

## The goal

The questions veri's most-patched modules keep answering separately get one owner each: what a
test file and its cases are, what a leaf's report says, and what the frozen record holds. A bug
in one of them is then fixed once, and tested without a process.

### What ADR-0030 requires of a ported case

`docs/adr/0030-tests-change-by-parallel-change-and-mutation-parity.md`, as `SKILL.md:439-447`
and `:1004-1013` run it:

- A port is a `⟦replaces-case⟧` step naming `skills/tdd/scripts/tests/py/test_tests_frozen_process.py`
  and up to about a dozen of its cases by exact name, so the 271 cases take about 23 steps.
- The replacement drives unchanged code, so its Red reports `AGAINST_UNMODIFIED: PASSES` and the
  step takes the pin path; its Green deletes exactly the named cases.
- Production is frozen (contract (a)): a seam the port needs lands first, in its own refactor.
- verify-green's PASS stands only once `mutation-parity.sh` on the step's pairs table exits 0.
  Each deleted case has a valid mutation (the old case red, another case of its suite green)
  that turns its replacement, or a named kept case, red. A mutation inside `case_history.py` or
  git that only a `test_case_history` case catches makes the old case redundant, not ported.
- A case with no valid mutation is never deleted: it goes under `## Owed by a human`.

## PRD 017.1: test-case reader

**What you get:** runs on Go, JS and Python repos classify test files alike, and a deleted or
renamed Go or JS case is seen. **Depends on:** nothing.

| ID | Requirement | Why |
|---|---|---|
| R1 | One module, `case_reader.py`, answers whether a path is a test file; no other veri module holds that pattern. | Five answers disagree today. |
| R2 | `production-frozen.sh` and `transform-touches-tests.sh` treat `*_test.go`, JS `.spec`, `test_*.py` and `*_test.py` files as test files. | A transform can edit a Go test unnoticed today. |
| R3 | Cutting a test source into cases lives in `case_reader.py`, with every recorded digest unchanged. | The cut has no git in it, and 834 lines surround it. |
| R4 | `wrong_test_route.py` builds no per-language pattern of its own. | Language support lands twice today. |
| R5 | A Go or JS case renamed with its body unchanged is recognised as a rename. | Otherwise R6 refuses a legitimate rename. |
| R6 | The deleted-case guard refuses a Go or JS case added by an earlier step and deleted by a later one. | The guard sees only pytest cases today. |
| R7 | A file-defined helper's body ends at the next top-level definition in any language, so it never takes in a later case (#2931). | A Go helper's body runs to the next `func` today, so a Python helper swallows later cases. |
| R8 | Finding where a case's call ends ignores parentheses inside string literals (#2970). | An unbalanced literal makes a case body too long, so check-earlier calls an unchanged case edited. |

**After landing.** "Test-case reader" goes into `CONTEXT.md` as PRD 017.14, and the deleted-case
refusal's "pytest cases" wording (`verify.py`) becomes PRD 017.13; both are settled decisions above.

## PRD 017.4–017.12: tests_frozen without a process

Each sub-PRD moves one command family (table above) from `test_tests_frozen_process.py` into
the fast tier, as in-process cases against `veri/tests_frozen.py` with `case_history` faked or
fed, under ADR-0030 as summarised above. A case stays in the process tier only when it needs a
real git repository: its mutation turns no fast-tier case red. `test_tests_frozen_record_check_process.py`
is the entry-point contract (`tests-frozen.sh` against files and a real repository) and stays
as it is.

Each sub-PRD is worth having alone: `make unit` then catches a regression in that command which
only `make test` caught before. **Order:** 017.4, 017.5, then 017.6–017.12 in any order, smaller
first as numbered. Every sub-PRD after 017.5 depends on the `fed_history` fixture 017.5 creates;
017.10 also depends on its own seam row. All of them edit `test_tests_frozen_process.py`, in
different cases.

Rows of the same shape repeat per family, so each sub-PRD's criteria stand on their own.
