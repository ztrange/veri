# PRD 017 requirements: three deep modules under the hot spots

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: 017.1 and 017.3 are filed; 017.2 and 017.4 are outlines.**

## The goal

The questions veri's most-patched modules keep answering separately get one owner each: what a
test file and its cases are, what a leaf's report says, and what the frozen record holds. A bug
in one of them is then fixed once, and tested without a process.

## PRD 017.1: test-case reader

**What you get:** runs on Go, JS and Python repos classify test files alike, and a deleted or
renamed Go or JS case is seen. **Depends on:** nothing.

| ID | Requirement | Why |
|---|---|---|
| R1 | One module, `case_reader.py`, answers whether a path is a test file; no other veri module holds that pattern. | Five answers disagree today. |
| R2 | `production-frozen.sh` and `transform-touches-tests.sh` treat `*_test.go`, JS `.spec`, `test_*.py` and `*_test.py` files as test files. | A transform can edit a Go test unnoticed today. |
| R3 | Cutting a test source into cases lives in `case_reader.py`, with every recorded digest unchanged. | The cut has no git in it, and 834 lines surround it. |
| R4 | `wrong_test_route.py` builds no per-language pattern of its own. | Language support lands twice today. |
| R5 | A Go or JS case renamed with its body unchanged is recognised as a rename. | Otherwise R6 refuses a legitimate rename. |
| R6 | The deleted-case guard refuses a Go or JS case added by an earlier step and deleted by a later one. | The guard sees only pytest cases today. |
| R7 | A file-defined helper's body ends at the next top-level definition in any language, so it never takes in a later case (#2931). | A Go helper's body runs to the next `func` today, so a Python helper swallows later cases. |
| R8 | Finding where a case's call ends ignores parentheses inside string literals (#2970). | An unbalanced literal makes a case body too long, so check-earlier calls an unchanged case edited. |

## PRD 017.2: leaf report reader (outline)

**What you get:** one definition of a malformed leaf report, so an unreadable one is always exit 2.
**Depends on:** #2878, #2881. Covers `report_read`, `_lines_with`, `same_reject.py` and
`build_develop_prompt.py`, read against the `REPORT-FORMAT` declarations.

## PRD 017.3: frozen record

**What you get:** a verified refactor or a diff-checked step no longer leaves a record that
check-earlier refuses, and the record's format, path and pass marker live in one module,
`frozen_record.py`, that other modules ask instead of reading its files. **Depends on:** R9
nothing; R10 #2942, #2994, #2998; R11-R13 the 017.1 issues editing `tests_frozen.py`.

Measured at `ace970e842`: `tests_frozen.py` is 925 lines, 129 of its 178 commits start `fix`;
`supervise.py:122,128,468` and `wrong_test_route.py:156-158` read its files through private
names; 390 process cases and 83 unit cases cover it.

| ID | Requirement | Why |
|---|---|---|
| R9 | The check-earlier pass marker's path, its writing and the check that it is current live in `frozen_record.py`; `supervise.py` asks it and names no `tests_frozen` private. | `supervise.py` reads the marker's lines itself today. |
| R10 | Only `frozen_record.py` builds a record's path or reads or writes its `format:`, `case:`, `body:` and `helpers:` lines; `wrong_test_route.py` asks it for a step's recorded cases. | `wrong_test_route.py:156-158` parses `case:` lines itself today. |
| R11 | `rerecord-refactored` exits 1, naming each case as `skipped:`, when a case it skipped is one check-earlier still refuses; exit 0 only when nothing is left stale (was #2943). | Exit 0 lets the conductor commit the step and bail at the next one. |
| R12 | `rerecord-earlier` rewrites a case's `body:` and `helpers:` lines together from HEAD, and drops a stale `helpers:` line for a case that calls no helper, so check-earlier exits 0 after it (was #2987). | A half-rewritten record makes check-earlier call an unchanged case edited. |
| R13 | Which steps are done at a revision is answered by `ledger.py`; `tests_frozen.py` holds no ledger-line pattern of its own. | `tests_frozen.py:308-355` re-parses the ledger. |

R12 corrects the outline's "without touching its `helpers:` line", which contradicted #2987's
own criteria.

## PRD 017.4: tests_frozen without a process (outline)

**What you get:** the frozen record's behaviour is pinned by unit cases, so `make unit` catches a
regression the process tier catches today. **Depends on:** 017.3. Each process case is replaced
under ADR-0030's mutation parity.
