# PRD 027 requirements: the conductor asks for a whole checklist in one call

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: DRAFT, from the 2026-11-13 efficiency analysis. Decisions D1–D7 were settled with Mario
on 2026-11-13. 027.1 carries rows and can be filed; every later sub-PRD is an outline that waits on
027.1's trial. Nothing is filed.**

## The goal

A conductor makes fewer requests to do the same run. Each request re-reads the conductor's whole
context, so a run of fixed calls made one request at a time costs one context read per call. A
*fused script* makes that run of calls itself and returns once: the conductor reads everything the
calls printed, and branches as it does today.

It starts with preflight, as a trial: preflight is a checklist with no leaf in it, and it repeats
on every session.

Target for 027.1: a fresh run's preflight takes at most 5 conductor requests (median 11 today).
The acceptance criteria are the behaviours that force it, never the count.

## What this PRD does not hold

- **The conductor's cost, context and restarts as measured things**: PRD 012 (`specs/prd-012.md`,
  CR1–CR3) owns them. This PRD changes how many requests a run needs, not how they are measured.
- **The size of procedure files read on demand** (`PREFLIGHT.md`, `DRAFT-PR.md`): ADR-0019 ruled
  on moving procedure text out of reach, and it is a different plan (D3).
- **What a leaf costs**: PRD 024.
- **The comments a run posts**: PRD 014.4a–g already made each one script call.
- **A program that replaces the conductor's loop**: recorded under *Open*, not planned (D1).

## Decisions

Settled with Mario on 2026-11-13.

| ID | Decision | Why |
|---|---|---|
| D1 | The conductor stays the loop. A fused script does one fixed run of calls and returns; the conductor branches on its exit. A program that drives the whole run is not planned. | Each fused script is worth having if the next never ships. |
| D2 | This is PRD 027, with PRD 012 named as the related plan. | Its own spec file and series; PRD 012's sub-PRDs already run to 012.15a. |
| D3 | The size of procedure files read on demand is out of scope. | ADR-0019; a different plan. |
| D4 | A fused script stops at the first call that is not clean, exits with that call's own code and names it. The conductor carries on from there by today's prose, which stays. | The script replaces only the path where everything passes, so the trial changes one thing. |
| D5 | Preflight is the trial. It is read over 10 conductor sessions on the fused preflight, and the cycle is planned only if all three hold: preflight requests per session at most half of today's median; no bail or wrong start traced to the script; and a count of the times the conductor did something by hand during preflight that the script's output did not prompt. | The third count is the evidence nobody has for or against fusing the cycle. |
| D6 | The fresh-run preflight is the first sub-PRD and the resume preflight the second. The trial is counted on whichever has landed. | The smallest slice worth having (P16), on the path with the least judgement. |
| D7 | A fused script prints every inner call with its exit code and what it printed, and writes what it settled to one file in the run's `.tdd/`. It never prints a leaf's or a suite's raw output file. | Output is nearly free next to a request: 1 KB is re-read by later requests at about a tenth of one request's cost. The conductor keeps the full picture, one call late. |

## 027.1 — a fresh run's preflight is one call

**What you get:** on a fresh run the conductor runs one command and gets back everything
preflight settles, or the exact step that stopped it.

**Depends on:** nothing.

`$S/preflight.sh` is the working name; the issue may rename it.

| ID | Requirement | Why |
|---|---|---|
| FP1 | `$S/preflight.sh <n> <slug>` performs `PREFLIGHT.md`'s steps 1 to 7 for a fresh run, in the order `PREFLIGHT.md` states them, with the claim (`unlabel-issue.sh <n>`) at the slot `SKILL.md` 1.6 gives it, and exits 0 only when every call was clean. | One request where there are 11 today. |
| FP2 | For every inner call it prints, in order, one line naming the call and its exit code, then what that call wrote to stdout and stderr, unchanged. | D7: the conductor still reads everything. |
| FP3 | It never prints the contents of a suite's or a leaf's output file; a test run appears as what `detach-command.sh wait` printed for it. | D7; the 25 KB of #3740. |
| FP4 | At the first inner call whose exit is not one `PREFLIGHT.md` treats as "go on" for that step, it runs no later call, exits with that call's code, and its last stdout line is `stopped at <step> <call>`. | D4. |
| FP5 | It handles no refusal itself: it calls neither `preflight-refused.sh` nor `event.sh bail`, posts no comment, and resets no branch. | D4: every refusal is handled exactly as today. |
| FP6 | The baseline and the full tier run through `detach-command.sh` start and wait. When a wait's slice runs out the script exits 3 with a last line `waiting on <name>`. | A Bash call ends at 10 minutes; exit 3 already means "call again" for a wait. |
| FP7 | Called again with the same arguments after an exit 3, it continues from that wait: no earlier call's effect happens twice (the worktree is not re-created, the claim is not re-applied, no second run of the same tier is started). | A script killed or timed out mid-run must be safe to run again. |
| FP8 | It follows `baseline-full-tier.sh`: on `reuse <seconds>` the full tier is not run and `full` is that figure. | `v0.1337`'s behaviour must survive the fusion. |
| FP9 | On exit 0 it writes `.tdd/issue-<n>-preflight` in the run's worktree, one `key=value` per line: the worktree path, the fast, full and one-test-target commands, `baseline` and `full` in seconds, the full-tier mode used, the default branch, the three leaf models and the timeout. It prints the same lines last. | D7; today these live in the conductor's memory. |
| FP10 | `.tdd/issue-<n>-preflight` is never committed: `ensure-run-state-ignored.sh` covers it. | It is run state. |
| FP11 | Run for an issue whose branch already holds a ledger, it exits 2 before any inner call, naming the resume path on stderr. | D6: resumes keep today's steps until 027.2. |
| FP12 | The slug is an argument. The script derives no slug and reads no flake: a red baseline or full tier stops it under FP4. | The five places the model judges stay the model's. |
| FP13 | `PREFLIGHT.md`, before its step 1, tells the conductor of a fresh run to run `$S/preflight.sh <n> <slug>`, to call it again on exit 3, to take preflight's values from its output, and on any other non-zero exit to continue from the step its last line names by the steps below. Steps 1 to 7 stay stated as they are. | D4: the prose remains the path for everything that is not clean. |
| FP14 | `SCRIPTS.md` has a catalogue entry for the script: its arguments, the per-call output format, the `stopped at` and `waiting on` lines, the file it writes, and its exit codes. | The catalogue is where a conductor looks a script up. |
| FP15 | A test fails when a numbered step of `PREFLIGHT.md` has no entry in the script's own ordered list of steps, or an entry there names no numbered step. | D4's cost: two descriptions of one procedure drift unless something ties them. |
| FP16 | Every event and comment a fresh preflight produces today is still produced, by the same inner script, in the same order. | ADR-0014, ADR-0005. |
