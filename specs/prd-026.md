# PRD 026 requirements: one dev session runs veri, and each question it cannot settle gets a session of its own

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: DRAFT, redefined on 2026-11-15 from Mario's ask of that day. It replaces the draft on
PR #3681 ("one dev session, plus a decisions session", settled 2026-11-11); *What happened to the
first draft* says what was carried and what was overturned. The decisions marked *proposed* are the
planning session's recommendations and wait for Mario's yes. 026.1 carries rows; the rest are
outlines. Nothing is filed.**

## The goal

`/vdev <lane> <N>` is the only session needed to run veri. It launches, judges, sets priority,
refills and merges; it resets its own context; and it says nothing a human has to read.

- **Status** is read from the GitHub issues (and later from the dashboard), never from the
  session's transcript.
- **A question vdev cannot settle** becomes a session of its own, one per question, where the
  human answers. vdev keeps running everything the question does not block.
- **Raw material** (logs, diffs, reviews, sweeps) goes to subagents; vdev's context grows only by
  conclusions.

Mario, 2026-11-15: "i want vdev to be the only one needed to work. start it with n, lane and its
own self resetter. i want it to open nested sessions for each open question that it is not able to
resolve and i want it to use delegate skill agressively to keep context short. it also should not
narrate almost anything."

## PRD 026.1: a question vdev cannot settle becomes a session of its own

**What you get:** when a run needs you, a session appears holding exactly that question, with the
options and a recommendation. You answer there. vdev never stops on it and never asks in its own
transcript. It works with today's two roles, so it is worth having if the fusion never ships.

**Depends on:** nothing.

| ID | Requirement | Why |
|---|---|---|
| QS1 | `skills/vdev/SKILL.md`, where it lists what it stops and asks for (D8's cases), says each such case first goes through `vjudge`, and that what `vjudge` settles is acted on and never asked. | D2. |
| QS2 | For a case `vjudge` does not settle, vdev writes `.tdd/questions/<id>.md` holding: what is being decided, each option in words, what each costs, vdev's recommendation, and the issue number when one is tied to it. | D5; P4's rule for a decision. |
| QS3 | vdev then calls `start_session` once for that file, with a brief that names the file's path and tells the session to load `vdev`'s question procedure, and nothing else of the question. | D3, D5: the file is the one copy. |
| QS4 | vdev does not wait for the session to start or to answer: on the same turn it carries on with every run the question does not block. | D4; P5. |
| QS5 | vdev sends one `PushNotification` naming the question when it writes the file, and none for a file that already exists. | D8. |
| QS6 | vdev opens no second session for a question whose file exists; after a reset it reads `.tdd/questions/` and treats each file without an answer as open and already asked. | D5; a reset must not ask twice. |
| QS7 | An issue-bound question's issue carries the `parked` label and comment as it does today. | D6. |
| QS8 | The question procedure tells the question session to: read the file, put the question to the human, write the answer under an `## Answer` heading in the same file, send vdev one line naming the file, and archive itself. It asks nothing the file does not ask. | D7. |
| QS9 | On a message naming a question file, vdev reads the answer from the file, never from the message, and acts on it. | P1; a message is not state. |
| QS10 | vdev deletes a question file only after it observes its own action on the answer in state (the label gone, the run resumed, the merge landed), and says so nowhere. | D7; P13. |
| QS11 | vdev's own transcript never contains the question's text or a request for an answer. | The ask's point: questions live in their sessions. |
| QS12 | `skills/vdev/REQUIREMENTS.md` carries a row for each of QS1–QS11's rules, and the unit is regraded. | A graded unit's prose needs its rows. |
