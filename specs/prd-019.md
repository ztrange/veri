# PRD 019 requirements: a bounded judgment before an exit-2 bail

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status: 019.1 is ready to file as one issue (see its Filing section); 019.2–019.4 are outlines. Nothing is filed.**

## The goal

When a script exits 2 at a site the procedure did not anticipate a way through, the run gets a
bounded second opinion before it bails. An opus `adjudicate` leaf reads the failure and answers
RETRY, ROUTE (an existing route) or BAIL. The exit-code API is untouched: the adjudicator never
turns a 2 into a 1, and the bail it fails to avoid keeps its original class.

Target: fewer system bails per run. No criterion fixes a number. The criteria are the behaviours
that deliver it.

## Decisions

Settled with Mario on 2026-11-08.

| Decision | Reason |
|---|---|
| Eligible: every exit-2 bail site **except** `killed-stuck` and `no-verdict`, `killed-external`/stop-requested, and preflight refusals. That makes 20 of the 24 measured bails eligible. | The two excluded classes already have their own budgets (`VERI_STUCK_RETRIES`, `VERI_NO_VERDICT_RETRIES`). A stop is a human's call, and a preflight refusal is not a bail. |
| The judge is a new `adjudicate` leaf, launched through `supervise.sh`, on opus by default, with its own knob `VERI_MODEL_ADJUDICATOR` (the narrower knob wins). | A leaf is recorded and supervised. A judgment made in the conductor's own context leaves no record and grows that context. |
| Outcomes: **RETRY** (the same command once more), **ROUTE `<token>`** (a route the procedure already defines at that site), **BAIL**. The leaf writes no file and no ledger line, and never relabels the 2 as a 1. | A judgment, not a repair. |
| Eighth budget axis: `VERI_ADJUDICATE_BUDGET`, adjudications per run, default `2`. `0` reproduces today's behaviour, and a bad value is a preflight refusal. CLAUDE.md's list goes to eight, and ADR-0020's stale count is corrected. | Per run, so that a step that keeps hitting exit 2 cannot loop. It is never folded into another budget (ADR-0020). |
| Each adjudication records an `adjudicated` event with the site, the outcome and the reason. A bail after a spent adjudication keeps its original cause and class. | `classify-bail.sh` and the system/process labelling stay as they are. |
| Inputs: the site's cause token, the command and its exit code, the last 50 lines of stderr, the route tokens defined at that site, and the step's ledger line. No leaf transcripts. | Keeps the prompt small and its cost bounded. |
| The rule lives once, in a new contingent unit `skills/tdd/ADJUDICATE.md` (read only on an eligible exit 2, per ADR-0019). Each site names it in one line, and it is recorded as ADR-0035. | One rule instead of N restatements. |
| RETRY at `ci-timeout` is one more full `wait-ci.sh` window. Each retry spends one unit of budget. | The cheapest RETRY that can change the answer. |
| One sub-PRD per site, `ci-timeout` first. | Largest measured group, 15 bails (P16). |

### Assumption made while writing (not asked)

- **The budget refills when a conductor starts.** A resume is a new conductor and gets
  `VERI_ADJUDICATE_BUDGET` again. Resuming is already an operator decision ("resume a bail once,
  then park"), so a carried-over counter would add state without adding a guard. The alternative,
  a counter persisted in `.tdd/` across resumes, stays open for 019.2.

## PRD 019.1: the mechanism, for `ci-timeout`

**What you get:** a run whose readied PR's CI is still pending at the deadline is judged once
before it bails `ci-timeout`, and gets one more CI window when the judge says RETRY.
**Depends on:** nothing.

### Requirements

| ID | Requirement | Why |
|---|---|---|
| R1 | Preflight checks `VERI_ADJUDICATE_BUDGET` (read as `${VERI_ADJUDICATE_BUDGET:-2}`). Anything other than a non-negative integer exits 2 before the baseline and names the variable. Pinned by a case. | A bad budget must not start a run. |
| R2 | `build-adjudicate-prompt.sh <n> <cause> <exit-code> <stderr-file> <command…>` writes a prompt carrying exactly the five inputs in Decisions: cause token, command, exit code, the last 50 lines of the stderr file, the route tokens `ADJUDICATE.md` lists for that cause (none for `ci-timeout`), and the step's ledger line. A cause not listed as eligible exits 2. Pinned by a case. | The inputs are fixed, and an ineligible site cannot be adjudicated. |
| R3 | `leaf-role.sh`, `leaf-model.sh` and `leaf-timeout.sh` know the `adjudicate` role. Its model is `VERI_MODEL_ADJUDICATOR`, else `VERI_MODEL`, else opus. The leaf is launched only through `supervise.sh`. Pinned by a case. | Same supervision and model rules as every leaf. |
| R4 | `parse-adjudication.sh <leaf-output>` reads the last `ADJUDICATION:` line. It prints `retry`, `route <token>` or `bail`, followed by the reason, and exits 0. It exits 2 on no such line, an unknown outcome, or a route token not listed for the cause. Pinned by a case per exit. | One parseable answer. Anything else is not an answer. |
| R5 | At each `ci-timeout` site in `DRAFT-PR.md`, a `wait-ci.sh` exit 2 that names no conflict, with budget left, launches the adjudicate leaf before any bail event. The adjudication spends one unit and records `adjudicated cause=ci-timeout outcome=<o> reason=<r>`. Pinned by a case. | The mechanism at its first site. |
| R6 | `retry` calls `wait-ci.sh` once more with a fresh window, and its exits are handled as at the first wait. `bail`, a parse exit 2, any `route`, or a spent budget writes the existing `ci-timeout` bail with its existing classification. Pinned by a case per branch. | The judge can only add a chance. It cannot change what a bail is. |
| R7 | With `VERI_ADJUDICATE_BUDGET=0`, no adjudicate leaf runs and the `ci-timeout` path is as before. Pinned by a case. | `0` is today's behaviour, exactly. |
| R8 | `metrics.sh` prints adjudications per outcome, and the adjudicate leaf's cost under its own role. Pinned by a case. | Whether the judge pays for itself can be read off the report. |
| R9 | *(Done in the PR that adds this spec: `docs/adr/0035-an-exit-2-is-judged-once-before-it-bails.md`.)* | The decision is recorded once. |
| R10 | Documented through the `## Requirements` rows below. | Docs change with the behaviour. |

## PRD 019.2: `ci-conflict` (outline)

**What you get:** the second conflict after the one-rebase path is judged before it bails, and
`ROUTE` may name that path's rebase. **Depends on:** 019.1. Open: whether the budget persists
across resumes (recommendation: no, it refills).

## PRD 019.3: `pr-ready-failed` (outline)

**What you get:** a `pr-ready.sh` failure is judged, and RETRY readies the PR again.
**Depends on:** 019.1.

## PRD 019.4: the remaining eligible sites (outline)

**What you get:** `report-missing`, `replaces-report-failed`, `step-add-refused` and the other
exit-2 bails `BAIL.md` lists are each judged. One issue per cause. **Depends on:** 019.1. Open:
whether to allow a **repair** outcome (removing a stray file, fixing a bad pin record, the
#2561 stray-file and #3357 bad-pin-record cases), which would need writes and its own guard.
Recommendation: a later PRD, after 019.1–019.3 show the RETRY/ROUTE/BAIL hit rate.
