# PRD 038 requirements: a step in one call, with seams the conductor can work in

The format is `specs/utility-skills.md`'s: each row makes one claim a reviewer, a grader or a test
can mark true or false; IDs are stable, and a dropped row leaves a gap.

**Status (2026-11-17): written against `e75e867579`. S1–S7 are Mario's answers of 2026-11-17,
each the planner's recommendation as kept by `vjudge`. Rows are written for 038.1 and 038.2 only;
038.3 to 038.12 are outlines. Nothing is filed. PRD 027's deferred D13 (`specs/prd-027.md:95`) is
taken by 038.6; `prd-027.md` is not edited.**

## The goal

The opus conductor spends most of a run's money on requests that follow a fixed procedure. The
target is to halve its requests on a clean run, and with them the growth restarts they cause,
without taking away its option to do any stage by hand. Fused scripts become **stages** that a
**runner** calls in series. The runner stops at a **seam** (the point between two stages) whenever
a stage does not end clean, or whenever the conductor asks it to. At a seam the conductor works
from today's prose, records what it did, and hands back to the runner.

## What this PRD does not hold

- **Moving per-call prose out of `SKILL.md`** (PRD 027 D11, ADR-0019). Open; see *Open*.
- **A program as the loop over steps** (PRD 027 D12). Open; see *Open*.
- **Fusing ⟦ci-repair⟧ and ⟦replaces-case⟧ Green.** They stay refused for the reason
  `specs/prd-027.md:290` (GH1) gives: they need the conductor's pairs table, or a CI wait after
  the push. Under this PRD they become a seam (S3).
- **Faster leaves or suites.** That is #4332 (records-only push re-runs CI), #4333 (leaves run the
  fast tier plus changed tests), #4336 (`grade-prose.sh --convert` re-parse) and #4337 (baseline
  skipped on CI green).

## Decisions

| | Decision | Rejected |
|---|---|---|
| S1 | A record is a cache. Where a stage's record disagrees with a committed fact (the ledger, git, `.tdd/verify-*.log`), the fact wins: the record is rewritten from it and an event is logged. A stale or missing record is never an exit 2. | Refuse with exit 2, as today: a stale cache would fail a run. |
| S2 | `revise` and `reroute` (038.9, 038.10) are stages the runner calls by default. `--hand revise\|reroute` keeps today's prose path. This makes the prose path an option and so does not reverse `specs/prd-027.md:105`. | Hand by default until measured: it would leave the saving unused. |
| S3 | The runner knows which step kinds each stage handles. It stops *before* a stage that does not handle the open step's kind, never calling it, with exit 1. | Calling the stage and passing its exit 2 through: a designed hand-off is not broken plumbing, and `classify-bail.sh` labels bails by 1 vs 2. |
| S4 | A seam's `next=` names prose by a heading anchor (`SKILL.md#<heading>`), checked by a test. | `file:line`, which drifts with every edit. |
| S5 | Order: the facts-over-records rule first (038.1), then the runner over today's stages (038.2), then one sub-PRD per new stage. | Runner first: it would wrap stages that still refuse on a stale record. |
| S6 | Any `SKILL.md` prose a sub-PRD adds is paid for by removing the same number of bytes in that sub-PRD. The ceiling is never raised. | Raising the ceiling, which no measured need justifies. |
| S7 | A stage done by hand ends with `seam-settle.sh <n> <stage> key=value…`, which writes the record that stage's script would have written. It checks the keys against the stage's seam contract. | (a) Each next stage re-derives the keys itself, and still needs a flag for `target_test`. (b) A stage done by hand cannot resume with `--from`. |

## Invariants this PRD keeps

- **The blind verifier.** No key a stage, the runner or `seam-settle.sh` writes reaches
  `build-verify-prompt.sh`. Its inputs do not change.
- **Every leaf launches through `supervise.sh`**, as the fused scripts launch them today.
- **Exit codes 0/1/2/3**, with 1 and 2 kept apart. A designed stop (hand, unmodelled, record) is
  1, never 2.
- **The eleven budgets stay on their own axes.** `revise` owns `REVISE_BUDGET` only and `reroute`
  owns `VERI_MISSING_REROUTE_BUDGET` only.
- **The committed ledger is the source of truth**, and `⟂ refactor pending` is cleared only by a
  verify-refactor PASS.
- **PRD 027 D1, D4, D7, D10.** The conductor stays the loop, and the runner is one more fused call.
  It stops at the first call that is not clean, prints call lines but never raw leaf output, and
  checks the tree before every irreversible act.
- **One skill snapshot.** Stages call each other through `fused.script()`, never through PATH.

## 038.1 rows: records are caches

| ID | Requirement | Why |
|---|---|---|
| SC1 | `green-half.sh`, `refactor-half.sh` and `step-close.sh` each take every value that has a committed source from that source: the open step from the ledger, `green_sha` from git, the verdict from `.tdd/verify-refactor.log`. Where the record holds a different value, they use the source's value and rewrite the record with it. | S1: the fact wins, and a stale cache never fails a run. |
| SC2 | Each rewrite in SC1 writes one `record-refreshed` event naming the stage, the key, and the old and new values, declared in `veri/event_table.py`. | S1's logged event: a refreshed record stays visible. |
| SC3 | A record names the open step when the two step texts are equal after one normalisation, defined once in `veri/ledger.py`, that drops `⟦…⟧` marks and a trailing `⟂ …` suffix. Every stage compares steps through that one function. | #4310: a marks-only plan rewrite made refactor-half refuse a correct record. |
| SC4 | When a stage needs a key with no committed source, and the record is missing or names another step, the stage exits 1, not 2. It prints `seam=<stage> code=1 reason=record next=seam-settle.sh <n> <previous-stage> <key>=…`. | S1 and S3: a missing record is a designed hand-off, not broken plumbing. |
| SC5 | Each stage that writes a record has a seam contract: the keys the next stage reads that have no committed source. The contracts are one table in `veri/seam_contract.py`, and `script-help.sh seam-settle.sh` prints it. | S7: the conductor learns from one place what a hand-done stage owes. |
| SC6 | `seam-settle.sh <n> <stage> key=value…` writes `.tdd/issue-<n>-<stage>` in the format that stage's script writes, with the open step from the ledger. It exits 0 on success. It exits 2, naming the reason, on an unknown stage, or on a missing, unknown or empty key. | S7. |
| SC7 | After `seam-settle.sh <n> red-half test_path=… target_test=…`, `green-half.sh <n>` runs as it does after a clean `red-half.sh`. A test drives both in-process and checks that green-half launches develop-green with those values. | S7: a hand-done stage resumes. |
| SC8 | `refactor-half.sh` runs, and does not refuse, when the only change to the open step since red-half wrote its record is to its `⟦…⟧` marks. This is the case from #4310. | Fact: a refusal on a stale record. |
| SC9 | Each hand path that `SKILL.md`'s Red, Green and Refactor sections describe ends with the `seam-settle.sh` call for its stage. `SKILL.md` stays within the 139,698 B ceiling, and the ceiling is unchanged. | S6. |
| SC10 | No value `seam-settle.sh` writes reaches `build-verify-prompt.sh`. Its argument list and the checks on its inputs are unchanged. | Invariant: the blind verifier. |

## 038.2 rows: `run-step.sh`

| ID | Requirement | Why |
|---|---|---|
| RN1 | When the open ledger step is a cycle step, `run-step.sh <n>` runs `red-half.sh`, `green-half.sh`, `refactor-half.sh` and `step-close.sh` in that order, each through `fused.script()`. After step-close exits 0, it prints step-close's `next=` line and exits 0. | The goal: a clean step in one call. |
| RN2 | At the first stage that exits non-zero, it stops, prints `seam=<stage> code=<c> next=<anchor or command>`, and exits with `c`. A stage's exit 3 is passed through as 3, meaning "still waiting, call again". | PRD 027 D4; the conductor branches on the code. |
| RN3 | Called again with no options, it resumes at the seam it stopped at. The seam is recorded in `.tdd/issue-<n>-step`, and the stage's own preconditions (038.1) decide whether that stage can run. | Rerunning resumes at the seam. |
| RN4 | `--from <stage>` starts at that stage. An unknown stage name exits 2. | S7: hand back after a stage done by hand. |
| RN5 | `--hand <stage>`, which may be repeated, stops before that stage with `seam=<stage> code=1 reason=hand next=<anchor>`. | The conductor keeps the option to own any stage. |
| RN6 | For an open step whose kind a stage does not handle, such as ⟦ci-repair⟧ or ⟦replaces-case⟧ at `green-half`, it stops before that stage without calling it. It prints `seam=<stage> code=1 reason=unmodelled next=<anchor>`. Which kinds each stage handles is one table in code. | S3. |
| RN7 | For an open step that is not a cycle step (⟦diff-checked⟧, ⟦skill-edit⟧, ⟦phases: …⟧), it exits 1 with `seam=none code=1 reason=kind next=<anchor>` until that kind's stage exists. | S3 holds until 038.3 and 038.4 land. |
| RN8 | A designed stop (hand, unmodelled, record, kind) exits 1, never 2. | Exit codes are the API: 1 ≠ 2. |
| RN9 | It prints each stage's call lines with their exit codes, and never the contents of a leaf's or a suite's output file. | PRD 027 D7. |
| RN10 | Every `next=` value it can print is a command or a `<file>#<heading>` anchor. A unit test enumerates them and fails when an anchor names no heading in that file. | S4. |
| RN11 | `SKILL.md`'s Red, Green and Refactor sections call `run-step.sh` once for a cycle step, in place of the four separate fused-call lines. `SKILL.md` gets no larger, and the ceiling is unchanged. | S6: the runner pays for its own bytes. |
| RN12 | `run-step.sh` launches no leaf itself. Every leaf is launched by a stage, through `supervise.sh`. | Invariant: stuck detection lives only in `supervise.sh`. |
