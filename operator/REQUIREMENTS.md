## operator/PRINCIPLES.md

| ID | Requirement | Why |
|---|---|---|
| P1 | A skill re-reads the state it decides on (ledger, `.tdd/`, `solvable-issues.sh`, PR state, processes) at each decision, never from its own memory. | This makes a context reset cheap. Rules were lost across resets at least 4 times. |
| P2 | P2's paragraph says the role state file (`.tdd/role-<role>.state`), and a handoff file, carry state only — what is running, parked, waiting and pending, and with what permissions — never a rule copied from a skill; on recovery or resume the rules come from re-reading the skill and this file. | Same reason as P1; the role state file is what recovery reads (RC4), and every session may hand off (PRD 041 D1). |
| P3 | Any waiting is done by a script that blocks until an actionable event and returns one line. No agent polls on a timer. | Each "still fine" tick costs tokens and changes nothing. |
| P4 | Every turn shows text, sized by the event. The dev session prints `.` and nothing else, as vdev's *Speaking* says, a run's events being on its issue. A human decision, where a session without `start_session` asks it in its own transcript (vdev's *When to stop and ask*), is written in full, asked once when it arises; later events never repeat it, and it is restated in full, never as a pointer, only when the human asks what is pending or its facts change. | "No need to narrate everything… tokens I'll never read." Mario asked four times for silence on routine watch events. 2026-10-21: an empty turn makes the harness ask for visible output (PR #2011), so the `.` stays. 2026-11-15 (PRD 026 D9): "no narration should be needed at all"; a run speaks through its issue. |
| P5 | A turn never ends while work is takeable. A turn that stops names why: queue empty, or the pending decision — once, by the turn that stops on it, not by every later routine-event turn. A stopping turn of the dev session prints `.` (its reason is the empty `solvable-issues.sh` or an open question file), except that in a session without `start_session` the turn that stops on a decision names it once. | An ended turn stalled #131 for 36 minutes. The dev session's reasons are already in state, and the human no longer reads its transcript (PRD 026 D9). |
| P6 | P6's paragraph says an operator role does no investigation in its own context: every lookup that takes more than one command — reading source, grepping for how a script works, git archaeology, a log, a diff, an issue sweep — goes to one subagent on the cheapest adequate model, which returns at most 10 lines. A leaf `.out` is never printed. | Keeps the session's context O(1). 2026-10-29: five sequential greps at 145k on Opus were 0.7M cache-read; the same reads in a subagent start near 45k on a cheaper model. |
| P7 | A cost is read from a report's `\| total \|` row, never by summing phase rows. | Summing double-counted and wrongly parked #388 and #409. |
| P8 | Lowering the conductor count stops no live run. The next exit is simply not refilled. | Running work is never wasted. |
| P9 | Launch order is `solvable-issues.sh` order minus the issues with a live conductor: one whose `conductor.pid` first-line pid answers `kill -0` and whose start time matches its second line, in P1's and P9's paragraphs alike. Any override is explicit, names who asked for it, and is written down in the role state file (P9's paragraph), never in a handoff. | Prevents a duplicate launch (#753) and silent reordering; the role state file is what every reset reads (RC4). A pid-only check fails on the two-line file (`illegal pid`) and passes for a recycled pid (#2537), so 2026-11-17's recovery read three live runs as dead. |
| P10 | An exit with no closing comment is checked for a usage limit, an API outage (a conductor log ending in an API-unreachable error, as vbail defines it) or Mac sleep before it is treated as a bail. | A limit, an outage and sleep all look like silent exits; one definition of an outage keeps P10 and vbail in step (PR #3488 review). |
| P11 | All writes stay in the project repo. A fix that belongs elsewhere is reported, not made, and every subagent brief says so. | Repo boundary. |
| P12 | No skill names a fact specific to veri's own repo. Project specifics come from the target repo's CLAUDE.md. | The skills operate veri on any repo. |
| P13 | A message to another session (vdev, or one of its question sessions) is self-contained (no option letters, no references only the sender saw) and is sent with `SendMessage` by the skill itself; the paragraph names no resetter. Only when delivery is held does the human get the message, as one fenced code block per recipient, named above it. (The P13 paragraph, **Messages between sessions are self-contained and sent by you (P13).**) | "dev thread does not know what a or b means." "why didn't you just send it yourself?" The resetter is gone (PRD 041.1). |
| P14 | A role never asks permission for an operation a run needs in order to continue, in the project repo: opening or updating a PR, filing, commenting on or closing an issue, editing repo files, running tests, removing a run's own files, worktree or branch, and any `gh` command. It does the operation and reports it. Asking is kept for the decisions its own skill lists (vdev's D8); P11's other-repo boundary and the rulings that hold a merge still apply. | Mario, 2026-10-21: "stop asking for permissions… you are in bypass permissions. i do not need to approve every seemingly dangerous command. just keep going." The dev session had asked another operator session whether to close #1835 after #2060 did its work. |
| P15 | P3's paragraph (**Wait in a blocking script, never on a timer (P3).**) names `$S/dispatch.sh` as the one blocking watch for operator sessions over conductors, launches and merges, and says it runs as one background command, never under a Monitor and never a hand-written script. | The repo's watcher is tested; each operator's hand-written copy was not (two false "#2173 exited" events, 2026-10-24). A Monitor wakes twice per event; a background command once, at exit (2026-10-29). |
| P16 | When the size of a slice and its cost pull apart, the smaller slice wins: a plan, an issue or a group of issues is never made larger to save money, and saving money is never the reason for its size. The rule grants no real-money spend, which stays the human's. | Operator, 2026-11-01: continuous delivery of value, shorter feedback loops, manageable bites of work. |
| P17 | The P13 paragraph says a comm check — the message `ping`, answered `pong` — runs only when a role starts or recovers from its role state file. | Operator, 2026-10-29: the ack was asked for on the comm check when an operator session starts or recovers, nowhere else; recovery no longer follows a reset (PRD 041.1). |
| P18 | The P13 paragraph says no message between operator sessions other than the comm check is answered with an `ack`, in either direction, and names no exception: a message gets a reply only when the receiver has a ruling, an instruction or a correction to send. | Bare acks were 13% of both sessions' cost on 2026-10-29 (PRD 012 section 7). The one exception, a recovered role's `ack` to its resetter, lost its only user with PRD 041.1. |
| P19 | The P13 paragraph says a sent message is confirmed by the effect it causes, read from state (P1) — the launch, the merge, the ledger change — never by a reply; until that effect is observed it is "sent, unconfirmed", never "delivered". | With no ack, "sent, unconfirmed" needs another way to close; the effect is already what the receiver re-reads. A send that reached a held inbox looked delivered. |
| P20 | P6's paragraph says independent single commands go out as parallel calls in one message, not one per turn. | Each sequential call re-reads the whole context; parallel calls pay it once. |
| P21 | *Operator principles* holds one principle, numbered with the next free `P` ID, stating: an operator role never asks the human through a question tool (`AskUserQuestion`) or a blocking end-of-turn box; a decision goes out once as plain text; only its own item waits; it is not repeated on routine turns; when the human's next message arrives, whatever it is about, the role answers it and then restates every pending decision in full; a dev session with `start_session` meets that restatement inside each pending decision's own question session, never in its own transcript (vdev's *Speaking*). ## operator/MAINTAINING.md

| ID | Requirement | Why |
|---|---|---|
| CM24 | A version is an annotated tag `vN.M` whose message is the capability, in the issue's words; there is no `VERSION` file and no changelog. (Versions are tags, opening paragraph.) | The tag is the only record of a version. |
| CM25 | One merged feature/fix issue is one minor bump, cut by the `vmerge` skill; docs, test and refactor PRs get no tag. (Versions are tags, opening paragraph.) | Tags mark capabilities, not every merge; `vmerge` is where this repo's merge procedure lives (#3550). |
| CM26 | Tags are listed with `git tag --sort=-v:refname`, never plain `sort`, because lexically `v0.9` outranks `v0.10`. (Versions are tags, first bullet.) | A lexical sort names the wrong latest version. |
| CM27 | Backfilling a tag needs `GIT_COMMITTER_DATE`, or retro-cut tags claim today's date. (Versions are tags, second bullet.) | A backfilled tag carries the date it describes. |
| CM74 | On the development Mac, suite stubs are `#!/bin/sh` and per-leaf helpers are functions sourced from `scripts/lib/` (#322, #323), because Homebrew bash starts slowly. (`make test` on the development Mac, first bullet.) | Start-up cost multiplies across every stub call. |
| CM75 | The `test` recipe gives every suite `LC_ALL=C`, `< /dev/null` and a symlink to the real `git` first on PATH; remote git is refused by `protocol.allow=never`, and `gh`/`curl` by the plugin `pytest_leg.py` loads. (`make test` on the development Mac, second bullet.) | Suites run fast and offline. |
| CM76 | The pytest leg pins `TMPDIR` to `/tmp` before it starts (#2354), so its `veri-pytest-*` run dir, `--basetemp` and every case's `tmp_path` live under `/tmp` whatever `TMPDIR` the caller set, matching CI; the pycache prefix, the full-run lock and `~/.veri-pytest-legs` are unaffected. (`make test` on the development Mac, third bullet.) | A local run's scratch matches CI's. |
| CM77 | macOS checks each new executable on its first run (~330 ms); the fix is `sudo spctl developer-mode enable-terminal`, enabling the terminal under Privacy & Security → Developer Tools and restarting it, and since a Claude desktop session is not covered, conductors are launched from the enabled terminal. (`make test` on the development Mac, fourth bullet.) | The per-executable check otherwise taxes every run. |
| CM78 | A speed issue states its acceptance criteria as behaviours only and quotes `make profile` before and after in the PR body; CI's `timeout-minutes` is the only wall-clock gate. (`make test` on the development Mac, last bullet.) | Speed is measured and reported, never asserted by a suite. |
