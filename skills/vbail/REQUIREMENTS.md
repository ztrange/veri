## skills/vbail/SKILL.md

| ID | Requirement | Why |
|---|---|---|
| B1 | Invoked as `/vbail <issue>`. `vdev` calls it on every exit that is not ✅ Done. | |
| B2 | It classifies from facts before acting, by one named source per class. First `$S/stop-reason.sh <issue>`'s output (B8). On `bailed …`, the `cause` of the last `bail` event in `.tdd/wt/<n>/.tdd/events.jsonl`, labelled with `$S/classify-bail.sh <cause>`: `killed-stuck` → killed-stuck; `no-verdict` → the no-verdict budget; `step-too-big` → the step-growth budget; `revise-exhausted` → revise-exhausted (`REVISE_BUDGET` or a ⟦skill-edit⟧'s); `needs-user` with `classification` `process` → a question, quoted from that run's `### ⛔ Bailed — <phase> (process failure)` comment and taken to the coordinator or the human (B6); `needs-user` with no `classification` field → the conductor stopped unmarked (a red baseline or any other preflight stop, with the issue comment `needs-user: the conductor stopped without a verdict.`), which no source tells apart, so it asks the human which; any other cause → a real bail of that cause and its classify-bail category. | Not from the comment's wording, and each class has one named source; a red baseline emits no bail event of its own and `classify-bail.sh` exits 2 on it, so the skill asks rather than inventing one (PR #2175 review). |
| B3 | A usage limit or sleep is not a bail: in the run's worktree `.tdd/wt/<n>`, it saves every uncommitted leaf edit, untracked files included, as a binary-safe patch under `.tdd/` (`git diff --cached --binary HEAD`), restores that worktree's tree, and when usage is back re-applies the patch there with `git apply` before resuming. | The saved edit comes back before the run continues, so no leaf work is lost to a limit or a sleep (PR #2175 review: the skill saved the edit but never said how to restore it). |
| B4 | A first real bail is resumed once with `$S/detach-leaf.sh $S/run-conductor.sh <n>`, with `VERI_NEW_SKILL=1` when the fix it needs landed after the commit recorded in `.tdd/issue-<n>-skill-commit`. | The resume command and the "landed after" test are things an agent can run. |
| B5 | *A second bail: park* says a second bail is parked with `$S/park-issue.sh <n> <cause> <unblock> [<pr>]`, which labels the issue `parked` and posts the cause and what would unblock it; then the next issue is taken. | A hand-posted comment leaves the issue unlabelled, so `parked-issues.sh` never lists it; vcoord (C13) and vdev (D13) already park only through the script. |
| B6 | Budget raises and ledger amendments come only from the coordinator or the human, and apply to that one resume. | |
| B7 | It leaves the run's logs in place. | |
| B8 | It runs `$S/stop-reason.sh <issue>` and the resume from the target repository's main working tree, and only B3's save and restore inside `.tdd/wt/<n>`. It reads stop-reason's first line as: `running` → the run is live, no action; `done <pr>` → not a bail, no action; `stopped <mode>` → a requested stop, not a bail, it reports the mode and takes no action; `usage-limit [<reset text>]` → a usage limit (B3); `outage [<text>]` → an API outage (B13); `bailed <phase> <classification>` → classified by the bail event (B2); `killed [<text>]` or `unknown [<text>]` → a sleep (B3) when a `gap <ts> <ts>` line follows (two consecutive events more than `VERI_SLEEP_GAP` seconds apart), else it asks the human. Exit 2 is no answer: it classifies nothing, takes no action, and reports stop-reason's stderr. | A sleep shows only as `gap` lines, `killed` is in no class, exit 2 had no instruction, and both scripts resolve `.tdd/wt/<n>` from the current directory (PR #2175 review); an outage printed as `unknown` reached the human instead of the outage section (PR #3488 review). |
| B9 | Every command runs from the target repository's main working tree, except the save and restore in the run's worktree `.tdd/wt/<n>`; the resume command runs from the main working tree. | An operator who cd'd into the worktree to restore would otherwise resume from there, and run-conductor.sh would resolve .tdd/wt/<n> from the wrong place. |
| B10 | *Budgets and ledger* says that a ledger step amended in place between runs (on the coordinator's or the human's word, B6) is committed with a `plan: rewrite` subject, so it becomes the growth baseline `ledger-growth.sh plan-sha` reads, and names the command line: `git -C .tdd/wt/<n> commit -m 'plan: rewrite — <why>' -- .tdd/issue-<n>.md`. | `ledger-growth.sh plan-sha` baselines on the newest `plan: scope` or `plan: rewrite` commit, so a step reworded in a plain `plan:` commit reads as a new line with no `add-ledger-step.sh` record and no `⟦added⟧`, and the resumed run bails `step-added-off-route` (#2246, draft PR #2347). The command line saves the role learning it (OT7). |
| B11 | *Budgets and ledger* names the command line that adds or replaces a step in the committed ledger: `$S/add-ledger-step.sh .tdd/wt/<n>/.tdd/issue-<n>.md after\|before\|instead-of <anchor-substring> <text>`. | 2026-10-29: five sequential greps at about 145k context learning how `add-ledger-step.sh` takes `instead-of` (PRD 012 section 7). |
| B12 | *A second bail: park* says that when what would unblock the run is another issue landing (a bug the run hit, filed or already open), the park adds `--blocked-by <that issue>`, so the parked issue lists it under `## Blocked by`: the blocker inherits the parked issue's selection band, and the parked issue is not selectable again until the blocker closes. | 2026-11-08 (Mario): #3284 was parked on #3357 with only a free-text `Unblock:` line and `Blocked by: None.`, so #3357 inherited nothing from a `priority` bug and nothing tied the two. |
| B13 | The section on a usage limit or sleep also covers an API outage, a conductor log that ends in an API-unreachable error such as `Can't reach the API server`: it gets the same save and restore, resumes once the API answers, and spends no resume. | #1974 and #2027 died together on ENOTFOUND (2026-10-21); an outage is no more the run's fault than a usage limit. |
