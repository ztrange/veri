(`### Red`.) | A red called in advance is harder to fool yourself with than one rationalised afterwards. |
| VSH6 | `### Red` says a test that passes is never weakened to fail: the step is dropped as redundant or its criterion re-phrased, and a criterion that cannot be pinned by a lightweight behavioural test stops for the user rather than being re-phrased into whatever is testable. | VSH7 | `### Green` writes the least production code that expresses the criterion, the obvious implementation of this criterion, never a constant return that only satisfies the assertion, and no generality, error handling or second case the test does not demand. (`### Green`.) | Minimal but honest code leaves the next test real work and pins this one. |
| VSH8 | `### Green` and `### Refactor` each say no test file is edited in that phase; a test that is genuinely wrong goes back to Red with the reason said. (`### Green`, `### Refactor`.) | Editing the test in Green moves the goalposts, and in Refactor removes the only check. |
| VSH9 | `### Green` runs the suites covering what changed, not only the new case, and makes one commit per step with the criterion in its subject; with a ledger, the step is ticked with `$S/tick-ledger.sh` in that same commit, never in one of its own. (`### Green`.) | The step commit is the step's atomic unit, and the ledger never runs ahead of the code. |
| VSH10 | `### Refactor` is bounded to the source files the step commit touched (`git show --name-only HEAD`, less what is not code), puts structural changes before cosmetic ones, commits each transform on its own as `refactor: <what>`, runs the covering suites after each, and reverts a transform that turns them red instead of chasing it green. (`### Refactor`.) | A bounded, attributable refactor keeps a break traceable and out of other PRs. |
| VSH11 | `### Refactor` says generality comes only from triangulation: overfit code is not hand-generalised there, but forced by a later step's test or noted as owed. (`### Refactor`.) | A general implementation nothing tests is worse than an obvious special case. |
