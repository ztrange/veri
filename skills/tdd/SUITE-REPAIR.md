## Before the Red of a `⟦suite-repair⟧` step — is the suite still red?

When the unchecked step carries `⟦suite-repair⟧`, run the full suite once on the current tip before its Red: the command is `$S/detect-test-command.sh --tier all`'s, run through `detach-command.sh` in the same start-then-wait shape as the preflight baseline. The red it was appended for may be gone (a rebase or an earlier step fixed it), and a repair step whose red no longer exists could only get an `UNTESTABLE` or a pin.

- **Green:** retire the step. Mark `step="$($S/next-unchecked.sh < .tdd/issue-<n>.md)"; VERI_ISSUE=<n> VERI_ACTOR=conductor VERI_STEP="$step" $S/event.sh suite-repair-retired`, tick it with `$S/tick-ledger.sh .tdd/issue-<n>.md "$($S/next-unchecked.sh < .tdd/issue-<n>.md)"` (no `--refactor-pending`, since no refactor loop follows), and commit the ledger with `git add .tdd/issue-<n>.md && git commit -m "plan: retire the suite-repair step, the full suite is green (#<n>)"`. Launch no leaf for it. Continue at *4. Draft PR*, whose full run, rebase and regrade follow as usual.
- **Red:** first run each test file the red output names alone, once, with the repo's own runner, then write `<red-file>`, listing the test files the red full run names, one per line (optionally followed by ` — ` and its first `FAIL` line), and `<alone-red-file>`, listing those of them still red when run alone, or the single line `none` when every one passed — never raw test output. Then ask `$S/suite-red-resume.sh flake suite-repair <red-file> <alone-red-file>`.
  - **Exit 0 (every file passed alone):** the red was a flake. `suite-red-resume.sh flake` has already written the `suite-flake` event, naming the files and `at=suite-repair`, so the conductor writes none of its own. Then retire the step exactly as the Green branch above does: the `suite-repair-retired` mark, the `tick-ledger.sh` tick (no `--refactor-pending`), the ledger commit, no leaf launched, and continue at *4. Draft PR*.
  - **Exit 1 (any file still red alone, or the output names no file):** the step proceeds to Red as below, the failing suites being its red evidence.

**After a `⟦suite-repair⟧` step's Red leaf and before verify-red,** run `$S/suite-red-resume.sh test-only <step-base-sha> <alone-cmd> <suite>…`, `<step-base-sha>` being the commit the step started from (`git log -1 --format=%H -- .tdd/issue-<n>.md`), `<alone-cmd>` the repo's one-test-file runner and each `<suite>` a suite the step's text names. It asks whether the Red leaf changed test files only, with every named suite then passing, no case deleted and no assertion removed:
- **Exit 0:** the repair needs no red bar. Tick the step with `$S/tick-ledger.sh .tdd/issue-<n>.md "$($S/next-unchecked.sh < .tdd/issue-<n>.md)"` (no `--refactor-pending`, since no refactor loop follows) and commit the ledger with the test changes under a `test:` subject. Launch no verify-red and no revise leaf, and never bail `revise-impossible`; continue at *4. Draft PR*.
- **Exit 1:** a production file is touched, or a suite is still red, or a case or assertion was removed: the ordinary Red, verify-red and revise path, unchanged.
- **Exit 2:** no answer could be obtained: **bail** with cause `no-verdict`, a system failure (`Read` `<base directory>/BAIL.md`).
